## 为什么不直接以 OWL 建设整个核心？

OWL 是标准语义描述/推理语言，商业有效，但它并不是对象存储、跨源身份、时序分析、ObjectSet、Function 执行、外部 Action 授权、审批、幂等与核验的替代实现。若将 OWL 作为唯一权威，仍需建设独立运营系统，并额外维持 OWL 到各类执行契约的映射。采用 Native 权威可将产品主目标（企业对象/运营分析/受控行动）放在首位。其代价是我们必须自研严格的类型/兼容/授权/版本质量门禁，不能退化为自由 JSON。

## 技术范围边界

- OWL/RDF/SHACL/SPARQL 是**可选标准语义适配/专业推理**，可显式报告 LOSSLESS_SUPPORTED/PARTIAL_SUPPORTED/UNSUPPORTED；不回写发布权威。
- P0 不以 Jena/TDB2 为必装运行依赖；Native Model 可在不启用 OWL Adapter 的情况下创建、验证和发布。
- Function 和 Action 是不同合同；所有有副作用的动作均走 Action Policy、审批、幂等和回执。
- 对对象实例、关系查询和聚合建立独立的权限与来源/准确性/新鲜度契约。
