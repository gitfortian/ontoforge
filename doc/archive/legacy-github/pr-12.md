## S0-MVP-0.1：最小可运行版本（一个版本、一个验收目标）

**唯一用户故事**：本机启动 PostgreSQL、Spring Boot 和 React 后，浏览器展示由真实后端 API 与 PostgreSQL 提供的状态；断开后端会报错，不展示虚构数据。

### 本轮实际交付
- Java 21 / Spring Boot：只读 `GET /api/system/status`，不堆积领域基础设施。
- PostgreSQL 17 + Flyway V1：只创建一个带随机 UUID 的持久安装标识；不创建用户/角色/工作空间/业务模型表。
- React + Vite / TypeScript：系统状态页面；模型、绑定、用户/权限均仅显示“规划中”。
- 本机专用 PostgreSQL Compose、启动说明和 S0 分版计划。
- CI：真实 PostgreSQL 17.11 Spring Boot/Flyway/API 集成测试和 TypeScript/Vite 构建。

### 本轮明确不实现
不做登录、用户管理、角色权限、工作空间、多租户、Native Model CRUD、真实 ObjectSet、Binding、Agent 或 Action。不建设空模块、复杂工作流和微服务。
**安全限制**：S0-MVP-0.1 无认证授权，仅限隔离的 localhost 开发使用；数据库演示口令不可用于正式部署，禁止公网暴露和真实生产数据接入。

### 人工验收（Windows 11）
1. 在仓库根目录执行 `docker compose -f infra/compose.dev.yml up -d`。
2. 执行 `mvn -f apps/api/pom.xml spring-boot:run`（Java 21 / Maven）。
3. 在 `apps/web` 执行 `npm install` 和 `npm run dev`（Node 22）。
4. 打开 http://127.0.0.1:5173 ，查看后端和数据库真实状态；API 为 http://127.0.0.1:8080/api/system/status 。
5. 停止后端，页面刷新应出现错误；重启后端后 PG installationId 应保持一致。
