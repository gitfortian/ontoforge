## 交付目的

基于已合并 **PR #8 / #9 的真实 PostgreSQL ObjectSet / Action 架构证据**，集中定义企业运营本体的 **Native DSL/AST V0.2**，避免将旧 OWL-first V0.1 当作未来 P0-A 后端的直接接口。

**本 PR 为架构候选合同及可运行验收，不是 Java Runtime，也不意味着 V1.2 已全面签收或允许跳过后续 Review/Release/Policy 实现。**

## 完整交付

### 5 类 JSON Schema (Draft 2020-12)

1. Native Ontology Package：ObjectType/Property/LinkType、Binding/LinkBinding、ObjectSetDefinition、Rule/Function/DecisionStrategy/Policy/ActionDefinition。
2. Normalized Typed AST：kind 鉴别节点及固定顺序的示例；引用解析、正式内容摘要和 SourceMap 仍需 P0 Compiler。
3. ObjectSet Typed Query：Filter/Traverse/Project/Sort/Aggregate/Page、类型引用与成本预算；拒绝 raw SQL、调用者自填授权。
4. ObjectSet Result：Accuracy、Completeness、Freshness 与已知子集 Scope；FAILED 不伪造 0 结果，PARTIAL 不冒充 COMPLETE。
5. Semantic Execution Record：联合知识/函数/规则/决策/Policy/Action 版本、主体、行动意图、授权、远端回执与业务结果；UNKNOWN 不能宣称成功，DENY / NEEDS_APPROVAL 不能执行。

### 制造质量黄金样例

- QMS QualityEvent → MaterialLot → ProductLot → WorkOrder → ERP CustomerOrder；
- 5 个 ObjectType、4 个 LinkType、5 个属性级权威 Binding、4 个 LinkBinding；
- READ_ONLY 风险 Function + EDIT_PLAN 冻结计划 Function、确定性 Rule/Decision、Policy 与 HIGH 风险 Action；
- 查询与 Typed AST、部分来源返回、执行失败无结果、UNKNOWN Action 证据。

## 评审请重点签收的核心决策

- [ ] Native Schema/AST 是业务模型的权威；OWL/RDF/SHACL 不控制核心模型保存/发布。
- [ ] ObjectType ≠ ObjectInstance，LinkType ≠ LinkFact；字段 Required ≠ 来源事实完整。
- [ ] Binding 按 **Property** 声明 Authority，冲突必须拒绝并治理；跨源 Identity 需批准。
- [ ] ObjectSet 是类型化 Lazy Query，QueryResult **Accuracy / Completeness / Freshness** 彼此独立。
- [ ] **READ_ONLY Function 不可输出 ChangeSet；EDIT_PLAN Function 仅产生拟议更改；Action 有独立 Policy/Approval/Executor/Idempotency/Verification。**
- [ ] 语义推理成立 ≠ 获授权；远端 Receipt 接受 ≠ 业务 Outcome 经核实；UNKNOWN 必须可对账。
- [ ] V0.1 的 IRI/DisjointClasses/equivalentClass 及复杂公理不能静默丢失，必须迁移 Manifest 与保真报告。
- [ ] 正式发布尚需：Registry/Import ACL、跨语言 Canonical JSON/Digest、Compatibility、Review、SourceMap、生产 Policy/Runtime。上述能力**不因本 PR Schema/CI 通过而视为完成**。
