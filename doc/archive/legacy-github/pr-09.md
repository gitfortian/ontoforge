## 已验证的事实

- PostgreSQL 17.11 (GitHub-hosted PostgreSQL Service Container)。
- **100,000 产品批次×8 Link = 800,000** 高扇出关系；**250,000×24 = 6,000,000** Link。
- 每组 **14 项 PR #8 基础回归 + 16 项新增门禁 = 30/30**；两组共 60 次测试通过，不代表 60 种不同用例。
- RLS 授权结果与按 workspace/visibility 显式逐表过滤的结果一致；数据库 Finance Role 具备专用金额访问权限，普通 Reader 无权聚合金额。
- 同幂等 Key 12 个并发请求只产生同一 ActionAttempt；两个不同 Key 操作同一批次互斥入队。
- 过期租约/被盗领 token 不允许开始新的派单；**旧 Worker 迟到错误不得覆盖新 Worker 状态**；已 VERIFIED 的状态不能被迟到 UNKNOWN 覆盖。
- 14 个不同对象的竞争 Worker 分配和模拟远端幂等回执；HTTP MockERP 与源版本/Policy/Function 变动负例。
- [完整两组通过的 CI Run #38681607499](https://github.com/gitfortian/ontology-system/actions/runs/38681607499)，各 Job Artifact 保存原始 JSON EXPLAIN ANALYZE。

## 需要评审签收的决策

- [ ] Native Ontology 权威、标准适配可选，继续遵从 V1.2。
- [ ] ObjectSet 类型化 Query AST / Physical Plan 解耦、业务对象去重、权限下推、查询预算。
- [ ] **PostgreSQL 作为 P0 对象/Link 索引、Registry/Binding 元数据和事务 Outbox 的默认基础候选**，但不定为任意高并发/亿级数据的永久唯一引擎。
- [ ] SourceFact、EditOverlay、EffectiveObject、ExternalReceipt 彼此有独立权威与状态语义。
- [ ] Function/Decision/Policy 不允许直接绕过 Action；Action 必须有独立审批/版本锁、目标竞争、租约 fencing、幂等与回执对账。
- [ ] 定义剩余 Gate：真实 ABAC 与撤权、超级节点/时态查询、冷缓存、多用户并发、增量索引、真实 ERP/QMS 沙箱与业务结果核验、完整 Semantic Execution Record。
- [ ] 不将本 POC 宣称为生产强一致、Exactly Once 或经过真实工业系统验收。
