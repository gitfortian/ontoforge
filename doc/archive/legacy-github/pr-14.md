## 产品正式命名：OntoForge · 砺元

**Onto**logy + **Forge**：不是单纯画出本体，而是在制造业数据、来源核验、对象关联和受控行动闭环中逐步“锻造”可信业务本体。“砺”意为磨砺与精炼，“元”意为根本与元素。品牌调性聚焦工业制造，不依赖特定外部厂商形象。

## 本 PR 直接交付
- Maven Parent：`io.ontoforge:ontoforge:0.1.0-SNAPSHOT`，根 `<modules>` 仅注册实际存在的 `ontoforge-boot`。
- 后端目录 `ontology-system-boot` → `ontoforge-boot`，Java Root `io.ontoforge`，启动类 `io.ontoforge.boot.OntoForgeApplication`，API service 字段改为 `ontoforge`。
- 前端目录和 npm name：`ontology-system-ui` → `ontoforge-ui`；浏览器标题与基础页面显示 `OntoForge · 砺元`。
- Spring application name、README、S0 模块规划、V1.3 总体架构的品牌信息、CI 路径和 Git ignore 统一更新。
- 新增 `doc/implementation/OntoForge-品牌与工程命名约定.md`，明确未来 `ontoforge-core`、`ontoforge-platform`、`ontoforge-dao` 等仅规划、不新建空模块。

## 特意保留的兼容性
- **不动** PostgreSQL 数据库名 `ontology`、用户、`ontology_pgdata` 数据卷、`platform_installation` 表、Flyway V1 checksum，也不删除已有本地数据。
- 保留 `/api/system/status` 路由、JSON 结构、安装 UUID、S0-MVP-0.1 版本、端口和本机专用开发限制。唯一 API 值变化是 `service: ontoforge`。
- **不动** Native DSL/AST V0.2 JSON Schema、`manufacturing.quality` 稳定包 ID、历史 POC/CI、GitHub 原始证据链接。
- GitHub 远端仓库 `gitfortian/ontology-system` **目前仍是原名**。仓库重命名需要在 GitHub 仓库设置另行执行，当前连接器不支持此操作；本 PR 不声称修改了 GitHub 远端名称。

## 验收
1. `docker compose up -d`，已有本地 Postgres 数据卷保持。
2. `mvn -pl ontoforge-boot spring-boot:run`（Java 21）。
3. `cd ontoforge-ui && npm install && npm run dev`（Node 22）。
4. http://127.0.0.1:5173 显示 OntoForge · 砺元；http://127.0.0.1:8080/api/system/status 的 `service` 为 `ontoforge`，installationId 与迁移前相同。
5. CI 必须通过 PostgreSQL 17 + Flyway 真实测试、TypeScript 构建、文档及 Native V0.2 结构回归；不得出现旧 Boot/UI 目录。
