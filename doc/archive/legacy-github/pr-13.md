## PR 描述（保留原文）

## 目的
响应 S0-MVP 本地启动验收后的工程规范反馈：参考 Yak Ops **实际根 Maven Reactor、Boot 模块、UI 模块及 Java 包组织**，替换仓库中的临时 `apps/api`、`apps/web` 命名。

**这是纯项目结构重构，不开发新功能。** 以已合并的 S0-MVP-0.1 为基础；保留 V1.3 架构、原 PostgreSQL Flyway V1、页面与 GET /api/system/status。

## 具体改动
- 根 `pom.xml` 成为 `io.ontology.system:ontology-system` 的 Maven Parent（packaging=pom），只注册一个**真实存在**的 Java 模块 `ontology-system-boot`。
- `apps/api` → `ontology-system-boot`，Java 入口规范为 `io.ontology.system.boot.OntologySystemApplication`；Controller 归于 `io.ontology.system.boot.controller.SystemStatusController`。
- `apps/web` → `ontology-system-ui`，npm package 同名；当前一个前端应用，**不套用 Yak Ops UI 内部多应用 `apps/web` Workspace**。
- 本地数据库 Compose 从 `infra/compose.dev.yml` 移到根目录 `compose.yaml`，使启动方式统一为 `docker compose up -d`。
- 调整 Maven/Node 构建路径、GitHub Actions 结构检查、`.gitignore`、README 与 S0-MVP 版本验收文档。
- 新增 `doc/implementation/S0-工程模块规划与命名规范.md`：完整规划 future common / platform / dao / core / business / spi / plugins / test-utils / e2e / dist / bom，但 **不创建空 Maven 模块，不提前建设登录/权限等功能**。

## 对照 Yak Ops
- 来源：[Yak Ops 根 pom.xml](https://github.com/weifuwan/yak-ops/blob/main/pom.xml)、[yak-ops-boot](https://github.com/weifuwan/yak-ops/tree/main/yak-ops-boot)、[yak-ops-ui](https://github.com/weifuwan/yak-ops/tree/main/yak-ops-ui)。借鉴命名和工程组织，不复制业务模块、MySQL 表、任务/CDC/调度实现。
- 保留早期 Spring Boot + PostgreSQL + React MVP，避免因追求模块数量提前引入无业务价值的空实现。

## 验收
1. 在仓库根目录运行 `docker compose up -d`。
2. 运行 `mvn -pl ontology-system-boot spring-boot:run`（Java 21 / Maven）。
3. 在 `ontology-system-ui` 中执行 `npm install && npm run dev`（Node 22）。
4. 浏览器仍访问 http://127.0.0.1:5173 ，API 仍是 http://127.0.0.1:8080/api/system/status 。
5. 以前创建的 PostgreSQL 数据卷**不必删除**；Flyway V1 和 installationId 必须保持原值。
6. CI 必须验证根 Reactor 正常编译、PostgreSQL 17 + Flyway 集成测试实际执行、TypeScript/Vite 构建通过，并拒绝残留 apps/infra 目录。

**不自动合并。** 先让本 PR 全部 CI 完成，再由你拉取并验收模块规范与本地启动。
