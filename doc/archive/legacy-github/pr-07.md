## 两轮 POC：已实测的架构不变量，以及尚未验证的生产选型

本 PR 最初记录第一轮 SQLite 9/9、模拟编辑 13/13 结果；本次继续添加**第二轮独立 HTTP / 四跳 ObjectSet 实验报告**和目录索引。不覆盖或删除第一轮报告，仍只有文档变更。

### 第二轮新证据

- POC-Query：Python/SQLite 内存库 **7/7**，工业对象四跳关联、重复 Link 去重、权限谓词、Keyset 分页；合成 5k/20k/50k 数据集记录样本 median/p95。
- POC-Edit：独立 TCP/HTTP 模拟 ERP、独立持久账本、SQLite 事务 Outbox、真实崩溃 Worker 子进程 **17/17**；覆盖收件方已落账但响应丢失、Worker 在调用前/记录回执前退出、UNKNOWN 对账、同 Key 重放、版本漂移阻断和 SourceFact/EditOverlay 冲突。
- **PostgreSQL 没有执行**：当前研究环境无 PostgreSQL 服务端也无法安装。PG17 DDL、RLS、EXPLAIN JSON、PostgreSQL Outbox/SKIP LOCKED 候选、PowerShell/Docker 脚本都只在源码 ZIP 中备妥，必须本地实测。

### 建议的架构判断

- 可作为后续 Native DSL/AST V0.2/ADR 的原则：逻辑 ObjectSet 与物理查询计划分离、唯一业务对象聚合、权限执行、中间结果安全、运营 EditLayer 和源事实分离、Action 版本锁/幂等/UNKNOWN 回执对账。
- 不可冻结：PG vs 图/搜索引擎的物理存储、PG 多 Worker Outbox、一致性/Exactly Once、真实企业 ERP/QMS 写回及可重建决策证据链。
- **下一门禁**：使用 Windows 本地 PG17 跑 EXPLAIN/RLS/多规模多并发和外部 HTTP+PG 事务 Outbox 断点测试，在实际执行证据前暂缓物理实现选型。
