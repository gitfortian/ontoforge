## 重点研究与核心发现

1. OMS / Object Database / Object Set Service / Object Data Funnel / Functions / Actions 的职责与关联；Schema 与真实实例分离。
2. Backing Datasource、对象主键、LinkType 来源、列级 MDO、增量/乱序索引、必填属性跨源缺失的实质性限制。
3. ObjectSet 的 Lazy 过滤/遍历/聚合和结果精度，不等于内存对象数组；字段 Searchable 与 Query AST 的服务端校验。
4. Function-backed Action 与普通计算函数的关系、自动升级导致的 Action 权限行为变化风险。
5. Action 参数、提交条件、无副作用 Preview、外部 Webhook、幂等 UNKNOWN 及成功 Action Log 与失败 Metrics 的区别。
6. Object Storage v1/v2 的 Writeback/Materialization 差异；对象行列权限的读时过滤与派生导出的 Mandatory Control 传播差异。
7. 制造质量 LOT→WorkOrder→CustomerOrder→Action 黄金故事；明确两个优先 POC：POC-Query、POC-Edit。

## 评审时最重要的决定

- [ ] 接受 Palantir 对标的是原生产品抽象与可验证原则，不是复制私有分布式拓扑。
- [ ] ObjectSet 必须是可组合、类型化、支持 Lazy 执行的逻辑查询表示。
- [ ] Native Schema/Binding/IndexBuild/OperationalEdit/ExternalReceipt 必须分开生命周期。
- [ ] Function 可以计算 EditIntent/ChangeSet，但正式有副作用修改必须经过 Action 边界。
- [ ] Action 绑定 FunctionReleaseDigest、EffectScope；变更需重审，不能靠自动升级漂移权限。
- [ ] 查询权限、派生输出/导出标签与来源撤权均有独立可测试 Gate。
- [ ] 底层物理存储、编辑覆盖层和一致性机制需完成 POC 才冻结。
- [ ] 不修改 V1.2 正文和已合并 DSL/AST V0.1；是否吸收到后续 ADR 和 V0.2 由单独评审决定。
