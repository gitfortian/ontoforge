> **事实基准**：2026-10-16 `main`（0.2 [#7](https://github.com/gitfortian/ontoforge/pull/7)、0.3 [#11](https://github.com/gitfortian/ontoforge/pull/11)、0.4 [#13](https://github.com/gitfortian/ontoforge/pull/13) 已合并）。Windows 11 用户本机 PostgreSQL 真实验收 **NOT RUN**；不存在正式企业 Release、权限/Action/真实工业实例。

## 快速使用（给第一次了解砺元的人）

一句话认识砺元：**先为业务事物建立受控语义模型，再通过有来源的绑定得到真实对象与关系；经授权查询/计算提出决策；需要变更外部业务状态时，还须审批、执行回执与结果核验。**

```text
业务术语与共识
  → 模型包 / ObjectType / Property / LinkType（已实现本地基础）
  → 草稿 → 校验 → 本地不可变快照 / 结构差异（已实现本地基础）
  → ChangeSet → 可信 Review → 正式 SchemaRelease → Activation（P0-B 待研发）
  → SourceFact / Data Binding / 身份核验 → 真实 Object / LinkFact 投影（P1 待研发）
  → ObjectSet → QueryResult + 来源/权限/时效证据（P1 待研发）
  → Rule / Function / Decision → Agent Context（P2 待研发）
  → Policy / Approval → Action / Outbox → ExternalReceipt / OutcomeVerification（P3 待研发）
```

**阅读方法**：表格中「阶段」标记该词所属功能的目前交付深度，**“合同已存在/POC/规划”不代表真实功能已上线**；“S0 已实现”仅代表隔离研发主线子能力通过自动化，**不是生产部署**。所有定义以砺元当前约定为准；外部标准或竞品的同名词可能具有别的含义。

## 先读这 14 组最容易混淆的概念

| 不是一回事 | 如何向非技术用户解释 |
| --- | --- |
| **业务术语 vs 业务概念 vs ObjectType vs Object 实例** | 先说清“生产批次”是什么意思，再定义生产批次类型；真正的 LOT-042 要等来源数据接入。 |
| **ObjectType vs LinkType vs LinkFact** | 类型规定“是什么”和“允许怎样关联”；LinkFact 才是两个现实业务对象确实关联的证据。 |
| **Property vs FieldMapping vs Property Value** | 先定义“批次状态”这个属性，再规定来自哪张表/接口，最后才有批次 LOT-042 的实际状态。 |
| **模型包 packageId vs revision vs snapshotId vs releaseId** | 包的身份、草稿保存次数、本地冻结历史、正式可信发行各自独立。 |
| **草稿保存 vs VALID 校验 vs 快照冻结 vs 审批发布 vs 激活** | 能保存 ≠ 检查合格 ≠ 留历史 ≠ 被批准 ≠ 业务当前使用。 |
| **本地 SchemaSnapshot vs 正式 SchemaRelease** | 快照可用来追溯和比较，但没有可信审查就不能叫“已发布”。 |
| **Structural Diff vs Compatibility Report** | 看到“删字段/改关系”的风险，不等于已证明所有下游应用兼容。 |
| **SchemaRelease vs BindingVersion vs IndexGeneration** | 模型结构、来源映射和查询数据投影分别版本化、分别激活。 |
| **来源事实 SourceFact vs 读投影 Object/Link Index** | 源系统维护事实；砺元为了高效查询保留可重建的读视图。 |
| **SourceKey vs 跨源实体身份** | MES 的“10086”与 ERP 的“10086”不能未经证据就说是同一个对象。 |
| **ObjectSet vs 内存数组 vs QueryResult** | 对象集合是可组合、受控的逻辑查询；结果是一次执行及其质量证据。 |
| **完整性 vs 准确度 vs 新鲜度** | 已知子集里算得准，不代表全量都知道，也不代表足够新。 |
| **Function / Decision vs Action** | 计算出“建议冻结订单”不等于具备冻结 ERP 订单的权限。 |
| **Action 请求 vs ExternalReceipt vs OutcomeVerification** | 请求发出、远端接受、业务实际状态生效是三件事；UNKNOWN 不等于失败。 |

## 本词汇表的 5 项命名规则

1. **页面主文案优先中文**，首次解释可以附英文和固定 ID：展示“关系类型（LinkType）”，不要在同一个产品里混用“连线/边类型/关联表/Link 规则”表达同一概念。
2. **代码/API/JSON 字段维持既有合同原名**：`objectTypes`、`linkTypes`、`sourceTypeRef`、`targetTypeRef`、`expectedRevision`、`payloadSha256` 等；文案统一不触发数据库字段重命名。
3. **产品按钮分清信任层级**：`保存草稿`、`检查模型完整性`、`留存本地快照`、未来 `提交审核`、`批准发行`、`激活版本`；禁止把“留存快照”标为“正式发布”。
4. **涉及证据都说明作用域**：模型的“关系证据要求”、源字段的“来源证据”、审核的“审批证据”、动作的“远端回执/结果证据”不能都称一个“证据字段”。
5. **状态不能自动升级**：设计 Discussion/Accepted、代码开发/合并、自动化通过、用户 Windows 实测、正式发布是五个独立事实，开发报告必须分别记录。

## 01｜产品定位、领域认知与场景

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **砺元** | OntoForge | 企业原生的受治理运营本体产品，以可追溯的对象、关系、数据、规则和行动连接业务，不限定仅制造业。 | 不是某个工厂的 MES，也不是可视化画图软件。 | 产品定位 |
| **本体** | Ontology | 对业务概念、对象类型、属性、关系及相关语义约束的结构化表达；砺元进一步围绕查询与行动治理组织它们。 | 业务本体定义不等于真实业务数据已经接入。 | S0 基础 |
| **运营本体** | Operational Ontology | 能承接来源事实、查询、确定性分析和受控业务操作的本体体系。 | 不等于仅能推理知识的 OWL 图谱。 | 架构 |
| **受治理语义运营层** | Governed Semantic Operations | 语义定义、权限、数据来源、决策与行动证据相互约束的一层业务基础设施。 | 不是业务系统全部迁移到平台。 | 架构 |
| **业务术语** | Business Term | 团队达成共识的人类语言概念，如“生产批次”；包含定义、领域、同义词与责任人。 | 术语不自动是可查询 ObjectType。 | F24 规划 |
| **业务概念** | Concept | 对某类业务事物或事件含义的抽象认知，先解释业务边界再投影成技术类型。 | 概念不等于对象实例或数据表。 | F24 规划 |
| **语义共识** | Semantic Agreement | 业务、数据、技术等参与方确认同一个词在指定上下文中含义一致。 | 同名不代表语义等价。 | F24/P0-B |
| **领域** | Domain | 具有清晰业务职责的概念范围，如制造质量、设备维护、订单履约。 | 领域不等于某个物理数据库。 | 跨阶段 |
| **用例** | Use Case | 用户在场景中希望达成的业务目标，如“找出受质量事件影响的订单”。 | 用例不是 Java 类或 API 清单。 | 产品 |
| **黄金故事** | Golden Story | 贯穿入口、正常操作、异常恢复、可核验结果的完整端到端用户路径。 | 原型黄金故事与真实后端黄金故事必须分别标识。 | 研发治理 |
| **工作台** | `Studio` / `Workspace UI` | 用户进入本体设计、查看检查与管理历史的任务入口。 | 有界面不代表后端全套治理能力已具备。 | S0 已实现基础 |
| **工作空间** | Ontology Workspace | 规划中的多用户、对象归属和授权作用域。 | S0 本地模型包不是可信多租户工作空间。 | F01/P0-B |
| **产品功能编号** | F01–F29 | V1.3 保留的 29 个产品能力标识，按八个功能域组织。 | 某个子场景通过不等于整个 F 功能完成。 | 产品总账 |
| **能力成熟度** | Capability Maturity | 分别记录未实现、POC、基础可用、专业完善、生产验收等状态。 | 不能用 CI 项数换算产品完成百分比。 | 跨阶段 |
| **S0** | Engineering Foundation MVP | 已落地本地对象/关系定义、保存、校验与不可变历史的工程基础阶段。 | 不等于工厂生产可用。 | 已合并开发主线 |
| **P0-A** | Native Modeling | Native 本体建模与结构合法性能力，S0 已覆盖其部分真实子能力。 | 不意味着正式审核/发布可用。 | 部分已实现 |
| **P0-B** | Model Governance | 下一阶段的可信模型变更、审查、版本发布、激活和回退治理。 | 不是继续增强本地快照按钮。 | 待设计 |
| **P1** | Binding and Query | 连接来源、身份/关系投影、ObjectSet 业务查询与结果证据。 | 本体结构已存在不代表 P1 可用。 | 规划 |
| **P2** | Function and Agent | 确定性业务计算、决策策略以及受控 Agent 上下文。 | 不能把 LLM 推测当业务事实。 | 规划 |
| **P3** | Governed Action | 受策略、审批和结果验证约束的对外业务变更执行。 | 不是直连 PLC 的自动控制。 | 规划 |
| **P4** | Productization and Interop | 跨工厂可复制部署、标准适配、性能运营与正式交付。 | 不等于简单换一个产品名称。 | 规划 |

## 02｜本体语言、模型类型和身份

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **模型包** | `Ontology Package` / `Native Package` | 一个可版本化的模型定义容器，包含 ObjectType、LinkType 等声明与依赖信息。 | 一个包不等于一套运行对象数据。 | S0 已有基础 |
| **模型包标识** | packageId | 稳定定位模型包的字符串，如 manufacturing.production。 | 不是包版本号或草稿修订号。 | S0 已实现 |
| **命名空间** | Namespace | 用于组织和区分模型标识的语义空间。 | 不要求所有 Native ID 都变成 HTTP IRI。 | P0-B 规划 |
| **对象类型** | ObjectType | 规定一类业务对象有哪些属性、主键和语义，如 ProductionBatch。 | 不等于任何一条真实生产批次记录。 | S0 已实现 |
| **对象实例** | `Object` / `Object Instance` | 符合 ObjectType 的某个实际业务对象，如批次 LOT-042。 | 0.4 只定义类型，未创建真实对象索引。 | P1 规划 |
| **对象属性** | `Property` / `Property Definition` | 对象类型的一个有类型的字段声明，如 batchStatus。 | 不等于来源表的一列已经映射成功。 | S0 已实现 |
| **属性值** | Property Value | 某个对象实例在某来源/时态下的具体取值。 | 存在字段定义不代表有有效属性值。 | P1 规划 |
| **稳定标识** | `Stable ID` / `id` | 模型类型及属性在约定作用域中的内部身份，重命名展示文案不能随意改变它。 | 稳定 ID 不等于 API 名或业务主键。 | S0 已实现 |
| **程序名称** | `apiName` / `API Name` | 对应用/SDK 暴露的程序化命名合同，如 ProductionBatch。 | 修改 API 名可能破坏消费者；不等于 display label。 | S0 已实现 |
| **显示名称** | `label` / `Display Label` | 界面给业务用户阅读的名称，如“生产批次”。 | 允许翻译/重命名，但不能据此认定身份相同。 | S0 已实现 |
| **业务说明** | description | 解释类型或属性的业务定义、约束及适用范围。 | 说明不是机器可执行校验规则。 | S0 已实现基础 |
| **主键引用** | primaryKeyRef | ObjectType 指向其自身某个必填简单属性的身份字段引用。 | 不是跨系统自动身份融合规则。 | S0 已实现 |
| **对象主键** | Primary Key | 在某对象类型身份契约下唯一标识实例的关键属性。 | 不同数据源同名主键不自动指向同一实体。 | S0 合同；实例 P1 |
| **属性类型** | Value Type | STRING、INTEGER、DECIMAL、BOOLEAN、DATETIME、ENUM 等受限属性值类型。 | 不是外部数据库字段类型的无损复制。 | S0 已实现 |
| **枚举属性** | ENUM Property | 只能接受规定取值集合的对象属性。 | 枚举项顺序变化不一定是语义改变。 | S0 已实现 |
| **字段分类** | Classification | PUBLIC、INTERNAL、CONFIDENTIAL、RESTRICTED 的声明性信息分类。 | S0 字段有分类不等于已经实施访问控制。 | S0 声明已实现 |
| **必填** | Required | 该模型属性必须有明确值的结构约束；主键必须必填。 | 结构必填不表示来源事实一定完整。 | S0 已实现 |
| **可搜索** | Searchable | 声明属性在未来查询中允许作为检索条件的能力约束。 | S0 标记为可搜索不代表 ObjectSet 引擎已上线。 | S0 声明已实现 |
| **关系类型** | LinkType | 定义两个 ObjectType 之间允许的业务关联及其基数、证据要求。 | 不等于已有一条真实业务关系 LinkFact。 | S0 已实现 |
| **关系事实** | `LinkFact` / `Link Instance` | 两个实际业务对象确实存在关系的可追溯事实，需来源、身份与时间证据。 | 不能凭 LinkType 直接生成。 | P1 规划 |
| **关系来源端** | sourceTypeRef | LinkType 的起点对象类型引用，如 ProductionBatch。 | 不是实际批次实例的 sourceId。 | S0 已实现 |
| **关系目标端** | targetTypeRef | LinkType 的终点对象类型引用，如 WorkOrder。 | 不是实际工单外键已经解析成功。 | S0 已实现 |
| **关联基数** | Cardinality | 定义来源到目标的数量关系：一对一、一对多、多对一、多对多。 | 基数方向取决于 sourceTypeRef 到 targetTypeRef，不能反读。 | S0 已实现 |
| **一对一** | ONE_TO_ONE | 来源对象最多连一个目标，目标也最多连一个来源。 | 类型约束不表示真实关系已存在。 | S0 已实现 |
| **一对多** | ONE_TO_MANY | 单个来源可关联多个目标。 | 反向是多个目标可指向一个来源，非一对一。 | S0 已实现 |
| **多对一** | MANY_TO_ONE | 多个来源可以指向同一个目标，如多个生产批次属于一个工单。 | 不能将方向和来源端交换。 | S0 已实现 |
| **多对多** | MANY_TO_MANY | 来源与目标两端都允许多个关联实例。 | 多跳查询仍需业务身份去重。 | S0 已实现 |
| **关系证据要求** | evidenceRequired | 声明未来某类真实关联是否必须携带来源证据。 | S0 只是规则声明，并未产生证据。 | S0 已实现声明 |
| **同包引用** | Same-Package Reference | LinkType 的来源与目标必须指向当前模型包已有 ObjectType。 | 不等于 P0-B 后将允许跨包无锁引用。 | S0 已实现 |
| **自关联** | Self-Relation | 一个类型与自身建立关系定义，例如工单依赖工单。 | 仍需检查方向、循环与实际证据。 | Native 合同 |
| **模型接口** | `Interface` / `Polymorphic Contract` | 若干不同对象类型共用的可调用形状或查询能力。 | 当前不是已实现的 Native 多态接口。 | 未来设计 |
| **领域包分层** | L1–L4 Package Layers | Ontology Core、Manufacturing Foundation、Domain Pack、Enterprise Extension 四级模型复用结构。 | 是模型分层，不是四个独立运行进程。 | 规划 |
| **工业基础包** | Manufacturing Foundation | 工厂、批次、物料、设备、订单、工单及业务时间等跨工业场景通用类型。 | 不是把企业数据复制一份成为模板。 | 领域模板规划 |
| **行业领域包** | Domain Pack | 质量、BOM、供应链、维护等复用模型集合。 | 不是与通用核心共用同一发布权限。 | P4 规划 |
| **企业扩展包** | Enterprise Extension | 厂商/企业特有对象、术语、来源绑定和策略的拓展模型。 | 应以可审核依赖扩展通用包而不是直接覆盖。 | P4 规划 |

## 03｜Native 合同、草稿、版本与治理（P0-B 重点）

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **原生本体语言** | `Native Ontology Language` / `Native DSL` | 砺元的对象、关系、绑定、规则、策略等权威定义语法。 | OWL/RDF 是可选互操作适配，不是发布权威。 | 架构合同 |
| **类型化抽象语法树** | Typed AST | 将已校验 Native 定义解析/编译成显式类型和引用的结构化产物。 | 合法 JSON 不自动等于可信已发布 AST。 | 合同规划 |
| **模型结构定义** | Schema Definition | 描述“允许有什么对象/字段/关系”的定义。 | 不是已经存在的对象/关系事实。 | S0 基础 |
| **机器合同** | JSON Schema Contract | 约束文档结构、字段类型、枚举和必填的机器可读模式。 | Schema 合法不等于业务语义合理或获准发布。 | V0.2 合同已存在 |
| **草稿** | `Draft` / `Working Draft` | 当前可持续修改的模型包编辑内容。 | 草稿不是已发布 Release。 | S0 已实现 |
| **安全未完成草稿** | `WIP` / `Work in Progress` | 允许暂存未填完整但结构安全的模型，继续编辑。 | WIP 保存成功不等于模型通过校验。 | S0 已实现 |
| **草稿标识** | draftId | 唯一识别某条可编辑模型包草稿的数据标识。 | 不等于 packageId、snapshotId 或 releaseId。 | S0 已实现 |
| **草稿修订号** | revision | 每次成功保存的可写内容版本序号。 | 不等于 Native 语义版本或模型正式发布号。 | S0 已实现 |
| **乐观并发检查** | `CAS` / `Compare-and-Swap` | 保存时校验 expectedRevision，阻止旧编辑覆盖新内容。 | 不是业务审批锁，也不能消除所有跨用户冲突。 | S0 已实现 |
| **预期修订** | expectedRevision | 调用方声明期望修改的草稿修订；与当前不符应冲突拒绝。 | 不能由客户端强行覆盖现有修订。 | S0 已实现 |
| **当前校验修订** | validatedRevision | 哪一次草稿 revision 曾经完整通过校验。 | 只代表那个修订，改动后必须重新校验。 | S0 已实现 |
| **校验报告** | Validation Report | 结构/语义检查产生的状态和可定位问题清单。 | 不是审核意见、发布许可或运行时质量报表。 | S0 已实现 |
| **有效模型** | VALID | 特定 revision 满足当前 Native 定义与引用规则，可产生候选。 | VALID 并不代表已审核或已激活。 | S0 已实现 |
| **未完成模型** | INCOMPLETE | 结构安全但业务必填信息尚未补全，可保存后继续修复。 | 不准冻结成有效历史基线。 | S0 已实现 |
| **非法模型** | INVALID | 含不支持、矛盾或非法引用/身份等定义，应拒绝产生可冻结候选。 | 并非网络或数据库执行失败。 | S0 已实现 |
| **模型候选** | `Candidate` / `Native Candidate` | 服务端从当次有效草稿完整构造的 Native 模型包内容。 | 候选不是已签名、已审批的正式 Release。 | S0 已实现 |
| **本地模型快照** | `SchemaSnapshot` / `Local Snapshot` | 从已校验修订冻结的不可变模型内容，用于历史和比较。 | 不是正式审核、发布或激活。 | S0 已实现 |
| **快照标识** | snapshotId | 唯一标识某份本地历史快照。 | 不等于对象实例版本或 Release ID。 | S0 已实现 |
| **规范化 JSON** | `JCS` / `RFC 8785` | 把同语义 JSON 编为确定的 UTF-8 表示，供跨实现摘要与验证。 | 不是对数据来源真实可信的证明。 | S0 已实现 |
| **内容摘要** | `SHA-256 Digest` / `payloadSha256` | 对规范化的完整候选字节计算的 256 位内容摘要。 | 摘要检测变化，不代表审批人签名或授权。 | S0 已实现 |
| **幂等键** | IdempotencyKey | 确保相同操作重试能找回原结果而非重复创建历史。 | 幂等不等于跨系统 Exactly Once。 | S0 已实现 |
| **结构差异** | Structural Diff | 比较两份模型定义中类型、属性、关系的新增、删除和变更。 | 不表示已经验证所有消费者兼容性。 | S0 已实现 |
| **差异风险** | Structural Risk | 对删除关系、基数变化、分类变化、证据放宽等给出的初步风险标签。 | 风险提示不是正式兼容证书。 | S0 已实现 |
| **潜在破坏** | POTENTIALLY_BREAKING | 某次变更可能破坏既有引用或下游模型使用方式。 | 不是已知发生了业务运行故障。 | S0 已实现 |
| **治理复核** | POLICY_REVIEW_REQUIRED | 例如原需证据的关系改为不强制证据，需要额外治理判断。 | 不自动代表发布已被拒绝或允许。 | S0 结构提示 |
| **变更集** | ChangeSet | 基于确定的模型基线提出一组可审的语义变更，携带差异和意图。 | 不是普通 git commit，也不是直接写生产模型。 | P0-B 设计 |
| **变更提案** | Change Proposal | 业务责任人发起的待审模型修改请求，关联 ChangeSet 和说明。 | 不等于草稿上的一次保存。 | P0-B 设计 |
| **变更基线** | `Base Snapshot` / `Base Release` | 一份变更相对于哪一个确定不可变版本提出。 | 客户端当前页的未保存内容不能当审核基线。 | P0-B 设计 |
| **审批内容锁定** | Approval Digest | 将审查决议绑定内容摘要、锁定依赖及政策版本等不可变要素。 | 批准之后改一字都不能沿用旧批准。 | P0-B 设计 |
| **依赖锁** | `Dependency Lock` / `Lock Digest` | 固定导入模型包的版本和内容摘要，确保编译与审核可重现。 | 不是仅写 latest 的浮动依赖。 | P0-B 设计 |
| **语义兼容报告** | Compatibility Report | 分析变更对主键、LinkType、数据分类、依赖及消费者的潜在影响。 | 结构 Diff 只是输入之一，不等于完整报告。 | P0-B 设计 |
| **质量门禁** | Quality Gate | 在提交审核或发布前强制检查模型语义、完整性、安全风险和兼容性。 | 不是 CI 绿灯就自动允许发布。 | P0-B 设计 |
| **审查** | Review | 由可信身份的评审者对固定候选、差异和风险作出判断。 | 不等于自己点击“校验通过”。 | P0-B 设计 |
| **审查决议** | ReviewDecision | 对固定内容作出的同意、拒绝或退回等有主体有时间的记录。 | 决议与候选 Digest 不匹配就必须失效。 | P0-B 设计 |
| **批准** | Approved | 特定 ChangeSet 和内容摘要获得符合政策的可信审查许可。 | 批准尚不代表发布资源已经创建。 | P0-B 设计 |
| **正式模型发行** | `SchemaRelease` / `Immutable Release` | 已按治理规则批准并生成的不可变、可引用模型版本资源。 | 绝不可把旧 Local Snapshot 直接改名为 Release。 | P0-B 设计 |
| **模型发行标识** | releaseId | 标识某份正式已发布模型内容及其关联审查证据。 | 与 snapshotId 不共享语义和信任等级。 | P0-B 设计 |
| **包版本坐标** | Package Coordinate | 模型包 packageId 与明确 version 等形成的对外引用身份。 | 同一 version 的依赖/内容摘要仍需独立校验。 | P0-B 设计 |
| **模型语义版本** | Semantic Version | 业务兼容策略下的模型包版本，如主/次/修订等级。 | 不等于 revision=3 的草稿保存次数。 | P0-B 设计 |
| **模型注册表** | Registry | 持久登记可发布、已发布模型及依赖和检索元数据的受管目录。 | 不是文件夹中的 JSON 列表。 | P0-B 设计 |
| **编译器** | Schema Compiler | 将合法 Native 定义与已锁定依赖编为可检查、可验证摘要的发布产物。 | 不要用 OWL 推理器替代治理合同。 | P0-B 设计 |
| **发布** | Publish | 将经过批准的模型内容形成不可变发布记录和可引用版本。 | 发布不必自动切换现有消费者使用的版本。 | P0-B 设计 |
| **激活** | Activation | 将指定 Release 指向某工作空间或消费者当前有效模型的受控切换。 | 激活不是写回 ERP 数据或重建全部索引。 | P0-B 设计 |
| **当前有效版本** | Active Release | 由受控 Activation 指向、当前供指定范围采用的正式模型版本。 | 不等于最近创建的 Snapshot 或最新草稿。 | P0-B 设计 |
| **弃用** | Deprecation | 声明某个版本将停止推荐使用，保留可追溯的兼容/迁移期限。 | 弃用不等于直接删历史。 | P0-B 设计 |
| **退役** | Retirement | 按生命周期结束某版本可被新消费者使用的资格。 | 不能破坏既有审计记录或隐式撤销外部动作。 | P0-B 设计 |
| **回退** | `Release Rollback` / `Reactivation` | 在校验许可下把受控有效指针切回此前已发布的可信版本。 | 不是删除新版本或逆转 ERP 外部副作用。 | P0-B 设计 |
| **并行模型版本** | Schema Version Coexistence | 允许不同消费者在迁移期各自引用受控版本。 | 不能将所有客户端瞬间强切为新版本。 | P0-B 设计 |

## 04｜来源系统、数据绑定、实体身份与投影

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **连接器** | Connector | 安全连接 ERP/MES/QMS 等源系统、读取元数据和受控数据的适配接口。 | 连接器存在不表示所有字段已经授权映射。 | P1 规划 |
| **来源目录** | Source Catalog | 记录源系统、表/接口、字段及其版本和责任归属的可发现目录。 | 源表结构不是 Native ObjectType。 | P1 规划 |
| **数据绑定** | Data Binding | 将某来源的身份、字段和关系映射到已定义的本体对象/关系语义。 | 不等于把外部表改造成模型包类型。 | P1 规划 |
| **绑定定义** | BindingDefinition | 声明 sourceRef、来源版本、字段映射、身份规则、刷新方式等的版本化合同。 | 定义绑定不表示数据已同步成功。 | P1 合同 |
| **绑定版本** | BindingVersion | 绑定规则或来源映射的具体可追溯版本。 | 不能与 SchemaRelease 混为一个编号。 | P1 规划 |
| **绑定激活** | Binding Activation | 将某份经过授权的绑定版本投入实际对象/关系构建。 | 模型 Schema 发布不会自动激活所有 Binding。 | P1 规划 |
| **来源引用** | `sourceRef` / `Source Reference` | 指向受控连接注册表中的来源实体/接口标识。 | 不能把密码、Token 直接嵌入 sourceRef。 | P1 合同 |
| **来源模式版本** | sourceSchemaVersion | 来源接口/表的结构版本或可辨识指纹。 | 不等于 Native SchemaRelease。 | P1 合同 |
| **字段映射** | FieldMapping | 指明某来源字段为哪个 Native Property 提供属性值。 | 字段名相同也不能自动对齐权威。 | P1 合同 |
| **来源权威** | Source Authority | 某个来源是否被允许就特定属性/事实作出权威陈述。 | 是属性/事实级，不能凭某系统名决定所有字段权威。 | P1 规划 |
| **权威来源** | AUTHORITATIVE | 对指定属性的主权威事实来源，冲突必须有治理规则。 | 不意味着此来源永远最新或绝对正确。 | P1 合同 |
| **补充来源** | SUPPLEMENTAL | 可提供佐证/补充值但不能默默覆盖权威来源。 | 并非第二个平权 AUTHORITATIVE。 | P1 合同 |
| **源事实** | SourceFact | 从业务系统观察到的事实值及来源、时间、版本、授权上下文。 | 事实本身不等于本体投影或行动结果。 | P1 规划 |
| **源内标识** | SourceKey | 在某一个来源系统作用域内标记实例的身份字段。 | ERP 与 MES 的相同 SourceKey 不代表同一对象。 | P1 规划 |
| **实体解析** | Entity Resolution | 跨来源判断多条记录是否指向同一业务对象，并记录依据与冲突。 | 不可以仅按同名或同一数字键自动合并。 | P1 规划 |
| **身份规则** | IdentityRule | 规定来源键、对象身份及跨系统比对与证据处理的规则。 | 不是数据库唯一索引能完全替代的规则。 | P1 规划 |
| **受审跨源身份** | APPROVED_CROSS_SOURCE | 跨源对象等价关系有明确可审来源依据和冲突处置。 | 不能自动推断 owl:sameAs。 | P1 合同 |
| **本体对齐** | Ontology Alignment | 在不同术语、类型或来源体系间建立经审核的语义对应。 | 对齐建议不等于发布认可。 | F26/P1 |
| **融合** | Semantic Fusion | 在保持来源权威和冲突证据的条件下将多源事实提供为一致视图。 | 不是所有字段最后写入同一张宽表。 | P1 规划 |
| **映射漂移** | Schema Drift | 来源字段、类型或意义变化使既有 Data Binding 可能失效。 | 不是自动重建后即可忽略的变化。 | P1 规划 |
| **同步检查点** | Checkpoint | 记录已消费到哪个来源变更进度，以便恢复和去重。 | 不是正式模型快照 snapshotId。 | P1 规划 |
| **来源水位** | Source Watermark | 表示对象/关系投影已覆盖来源事实至哪个业务时间或更新点。 | 不能以当前机器时间代替来源水位。 | P1 规划 |
| **对象投影** | Object Projection | 把权威源事实按绑定生成可重建、便于查询的对象读模型。 | 不是 SourceFact 的原始权威存储。 | P1 规划 |
| **关系投影** | Link Projection | 把有证据的源关联映射为受权查询的 LinkFact 读索引。 | LinkType 存在不能自动投影 LinkFact。 | P1 规划 |
| **索引世代** | IndexGeneration | 一次对象/关系索引构建的明确版本，用于查询一致性和失效。 | 不等于模型包的发布版本。 | P1 规划 |
| **读取时有效视图** | EffectiveObjectView | 按权威、运营编辑、冲突与时间规则计算的当前查询视图。 | 不应静默将不同来源的冲突值覆盖。 | P1 规划 |
| **运营编辑** | OperationalEdit | 受控产生的本体侧业务变更意图与状态覆盖信息。 | 不等于无审批直接更新外部业务系统。 | P2/P3 规划 |
| **当前事实** | Current Effective Fact | 在指定时刻及授权范围内选择的有效业务值或关系。 | 不能把上一次缓存值默认为新鲜值。 | P1 规划 |
| **观察时间** | ObservedAt | 平台知道或接收到事实的时刻。 | 不等于事实在业务上开始有效的时间。 | P1 规划 |
| **生效时间** | `EffectiveAt` / `Valid Time` | 某业务事实在业务语境中成立的时间。 | 不等于数据库插入时间。 | P1 规划 |
| **来源撤权** | Source Revocation | 取消使用某来源数据的授权，并向投影、缓存、查询和派生物传播。 | 旧索引可查不意味着可继续展示。 | P1/安全 |
| **增量变更捕获** | `CDC` / `Change Data Capture` | 持续获取来源已发生的新增、修改或删除以更新投影。 | 不是所有系统都有同等 CDC 接口。 | P1 规划 |
| **对账** | Reconciliation | 比较来源、投影、业务回执或版本记录是否一致并给出异常处置。 | 数据同步对账与 Action 结果对账是两条不同业务链。 | P1/P3 |

## 05｜ObjectSet、查询计算及查询结果质量

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **对象集合** | ObjectSet | 在模型版本、来源时态和权限范围内可被计算的业务对象集合抽象。 | 不等于 Java List、固定顶点集合或保存的 ID 数组。 | P1 合同/POC |
| **对象集合定义** | ObjectSetDefinition | 保存一个可复用集合的 rootType 和查询语义。 | 不等于某次 QueryResult Snapshot。 | P1 规划 |
| **查询规范** | QuerySpec | 由 Filter、Traverse、Project、Sort、Page、Aggregate 等组成的类型化查询请求。 | 拒绝直接接受任意 SQL 字符串。 | P1 合同 |
| **惰性执行** | Lazy Evaluation | ObjectSet 运算先组合逻辑计划，必要时才真正读取业务数据。 | 不是在 Java 内存中先加载所有对象再过滤。 | P1 设计 |
| **过滤** | Filter | 按受控属性、类型和操作符选择对象实例。 | 非 searchable 字段不能无审核强制过滤。 | P1 合同 |
| **检索** | Search | 利用允许的字段或索引查找满足条件的对象。 | 不能用全文召回结果冒充精确身份命中。 | P1 规划 |
| **关系遍历** | Traverse | 按 LinkType 和方向从一个对象集合走到有关联的其他对象。 | 遍历的是有证据的 LinkFact，不是只看 LinkType。 | P1 合同 |
| **关联连接** | Join | 按身份/映射条件把两组数据组合，保留授权和去重语义。 | SQL 行数不直接等于业务对象数。 | P1 规划 |
| **投影选择** | `Project` / `Select` | 只返回用户需要且被授权的对象属性。 | 与 P1 的存储读投影不同，此处是查询列选择。 | P1 合同 |
| **排序分页** | `Sort` / `Page` | 按稳定顺序和游标返回结果的一段。 | LIMIT 小不意味着执行代价就小。 | P1 合同 |
| **聚合** | Aggregate | 按授权业务实体做 COUNT、SUM、GROUP 等计算。 | 来源部分缺失时聚合不得声称全量。 | P1 合同 |
| **实体去重** | Identity Deduplication | 按最终业务对象身份合并多条关联路径产生的重复命中。 | 不能仅按 SQL 表行去重计算订单金额。 | P1 规划 |
| **查询解释** | Query Explain | 展示语义运算、数据来源、预算与执行计划的可解释摘要。 | 不能泄漏无权源、敏感行和索引细节。 | P1 规划 |
| **查询预算** | Query Budget | 限制最大行数、遍历深度、成本、超时和扫描对象等。 | 不等于只给响应结果设 LIMIT。 | P1 规划 |
| **逻辑计划** | Logical Query Plan | 不依赖具体 SQL/图引擎的对象集合运算结构。 | 不是 PostgreSQL EXPLAIN 输出。 | P1 合同 |
| **物理计划** | Physical Query Plan | 把逻辑计划映射到 PostgreSQL、图/搜索或联邦执行的具体步骤。 | 可以换执行引擎而不改变业务语义。 | P1 规划 |
| **查询结果** | QueryResult | 数据、分页、来源/模型版本、质量和权限证据的完整返回合同。 | 不是只返回一个数组。 | P1 合同 |
| **准确度** | Accuracy | EXACT、APPROXIMATE、UNKNOWN 等结果精确性声明。 | 准确计算的已知子集仍可能不完整。 | P1 合同 |
| **完整性** | Completeness | COMPLETE、PARTIAL、UNKNOWN 描述授权范围内的来源覆盖。 | PARTIAL 不等于计算算法近似。 | P1 合同 |
| **新鲜度** | Freshness | FRESH、STALE、UNKNOWN 表示数据相对业务时效要求的状态。 | 最近查询过不代表来源事实够新。 | P1 合同 |
| **回答范围** | AnswerScope | REQUESTED_SCOPE 或 KNOWN_SUBSET 等，明确答案覆盖的实际范围。 | 不能把已知子集的 17 个说成全量 17 个。 | P1 合同 |
| **不完整来源** | SOURCE_PARTIAL | 某些来源未能访问、失败或延迟，查询只能覆盖已知部分。 | 不能让客户端显示 0 来掩盖缺失。 | P1 合同 |
| **高扇出** | `High Fan-out` / `Supernode` | 一个对象关联大量其他对象，使遍历、去重与授权代价陡增。 | 基础 POC 的快查询不是生产 SLA。 | P1 性能研究 |

## 06｜规则、函数、决策和 Agent

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **业务规则** | Rule | 基于已知事实与模型计算出约束、分类或判断的确定性定义。 | 规则命中不等于业务处置已批准。 | P2 规划 |
| **规则引擎** | Rule Runtime | 在声明的输入、版本和时态下执行规则并生成证据。 | 不能绕过读取权限和来源质量。 | P2 规划 |
| **函数** | Function | 可调用的可版本化业务计算能力，明确输入、输出、风险及副作用许可。 | Function 不是自动被授权写业务系统。 | P2 规划 |
| **只读函数** | READ_ONLY Function | 基于已有事实计算、过滤或解释而无外部业务副作用。 | 输出建议不等于 Action。 | P2 规划 |
| **编辑意图函数** | EDIT_PLAN Function | 返回拟议变更计划或 ChangeSet，不直接执行外部写操作。 | 返回计划不是完成写回。 | P2 设计 |
| **决策策略** | DecisionStrategy | 把业务条件、规则和明确输入转为确定性业务建议的策略。 | 建议不具有对外系统写入权限。 | P2 规划 |
| **决策记录** | Decision Record | 保存哪个模型/事实/规则版本得出何种业务结论的证据。 | 不能只保存自然语言解释。 | P2 规划 |
| **上下文引擎** | Context Engine | 为应用和 Agent 提供经身份、权限、版本和来源核验的结构化上下文。 | 不是无权限的全文拼接。 | P2 规划 |
| **智能体** | AI Agent | 可计划、选择工具并处理任务的模型驱动执行主体。 | 生成文本不是事实证明，也不是执行许可。 | P2 规划 |
| **智能体上下文** | Agent Context | 在某次任务内获准读取、附来源及有效期的业务对象与决策材料。 | 不能传入任意未过滤数据库明细。 | P2 规划 |
| **能力目录** | Capability Registry | 登记可被应用或 Agent 调用的函数/行动能力、版本和授权边界。 | 目录可见不表示当前用户能调用。 | P2 规划 |
| **工具调用协议** | `MCP` / `Model Context Protocol` | 让模型客户端按协定发现、调用受控工具及资源的接口形式。 | 有 MCP 服务不代表模型具备执行授权。 | P2 规划 |
| **开发套件** | SDK | 对外提供强类型对象查询、模型版本和执行能力的开发接口包。 | 不是直接透传内部数据库结构。 | P2 规划 |
| **提议反馈** | `AgentSuggestion` / `Feedback` | Agent 提出待审核的模型改进或业务建议。 | Agent 不直接成为 Native 发布人。 | F29/P2 |

## 07｜Action、外部执行与结果核验

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **业务动作** | `Action` / `Governed Action` | 经版本、Policy 和主体审查后提出或执行的可核验业务变更。 | 不同于 Function 计算输出或生成文字。 | P3 规划 |
| **动作定义** | ActionDefinition | 声明输入、目标、允许的业务效果、前提条件及执行适配器。 | 定义动作不代表可以立即调用。 | P3 规划 |
| **动作运行时** | Action Runtime | 对 Action 做授权、审批、排队、远程执行、重试和结果核验的系统。 | 不是一个直接调用 ERP 的 Controller。 | P3 规划 |
| **效果范围** | EffectScope | 限定一次 Action 允许影响的对象、字段、系统或业务资源范围。 | 同一用户有权限不等于可操作所有对象。 | P3 设计 |
| **动作预演** | Action Preview | 提交前展示将变更什么、预期影响和所需审批。 | 预演不是远程真实执行。 | P3 规划 |
| **动作审批** | Action Approval | 对锁定输入、Scope、Function/Policy 版本及风险批准业务执行。 | 模型 Release 审批不自动授权 Action。 | P3 规划 |
| **变更计划** | Business ChangeSet | Function/Decision 输出的业务对象/属性拟议更新集合。 | 应区分 P0-B 的“模型 ChangeSet”。 | P2/P3 规划 |
| **执行尝试** | ActionAttempt | 一次 Action 具体发起、认领、提交、重试或核验的生命周期记录。 | 一次逻辑动作可能有多次尝试。 | P3 规划 |
| **事务发件箱** | Outbox | 与本地 ActionAttempt 同一事务写入待发送记录，避免提交意图丢失。 | Outbox 写入不表示外部已处理。 | P3 POC |
| **执行工作者** | Worker | 从受控队列或 Outbox 认领动作并使用 Adapter 调用外部系统。 | 不能因进程重启丢掉已提交请求事实。 | P3 规划 |
| **租约** | Lease | 限制执行工作者在某段时间有权处理指定尝试。 | 租约过期不能取消已经发送的远端 HTTP。 | P3 POC |
| **认领令牌** | ClaimToken | 防止过期 Worker 回写覆盖新 Worker 状态的代际标识。 | 仅能隔离本地状态，不能撤销远端命令。 | P3 POC |
| **外部适配器** | Remote Adapter | 安全调用具体 ERP/MES/QMS API 并规范化回执的受控组件。 | 不允许用任意自由 SQL/HTTP 代替白名单适配。 | P3 规划 |
| **外部回执** | ExternalReceipt | 远端系统对某次请求的接收或处理确认。 | ACCEPTED 只是接收，不保证业务成功。 | P3 规划 |
| **执行结果未知** | UNKNOWN | 请求已可能到达远端，但当前无法确认最终业务效果。 | UNKNOWN 不等于失败，更不能自动重复发指令。 | P3 规划 |
| **结果核验** | OutcomeVerification | 独立读取业务状态并证明行动预期是否真正达成。 | 不能仅从 HTTP 200 推断。 | P3 规划 |
| **效果对账** | Action Reconciliation | 将执行意图、远端回执和最终业务事实比较并处理差异。 | 与数据同步 SourceFact 对账分开。 | P3 规划 |
| **来源已追平** | SOURCE_CAUGHT_UP | 源系统当前事实已观察到与获批 Action 目标一致的更新。 | 应先保证是同一业务对象与版本。 | P3 规划 |
| **补偿** | Compensation | 在业务可允许的情况下用新的审计动作纠正先前副作用。 | 模型回滚不能直接抹去已经执行的 ERP 操作。 | P3 规划 |
| **跨系统恰好一次** | Exactly Once | 跨 PostgreSQL 与外部系统原子执行的强语义，在当前产品不能无证据承诺。 | 幂等/对账降低重复风险但不创造原子事务。 | 安全边界 |
| **语义执行记录** | Semantic Execution Record | 记录模型/事实/函数/策略/审批/执行路径/回执/结果的综合可追溯证据。 | 合同 JSON Schema 存在不等于已生成真实审计证据。 | P3 合同 |

## 08｜授权、安全、审计与工程运营

| 推荐中文名称 | 英文 / 代码术语 | 砺元语境与例子 | 明确不能混淆 | 当前阶段 |
| --- | --- | --- | --- | --- |
| **可信主体** | Authenticated Principal | 经服务端实际身份认证的用户、服务或 Agent 执行身份。 | 客户端自填 role=admin 不是可信身份。 | P0-B 安全设计 |
| **身份管理** | `IAM` / `Identity and Access Management` | 企业人员、服务身份与组织权限的管理体系。 | S0 本地页面尚未接入真实 IAM。 | P0-B/P4 |
| **开放身份协议** | `OIDC` / `OAuth2` | 企业身份认证/授权集成可选协议。 | 协议列在设计中不等于已经有可信登录。 | P0-B 设计 |
| **访问控制** | `Access Control` / `ACL` | 在包、对象、属性、关系和操作上限定哪些主体可读写。 | 用户界面禁用按钮不等于后端拒绝。 | P0-B/P1 |
| **角色权限** | RBAC | 按可信角色授权某类操作的方式。 | 角色名称不能替代资源/范围检查。 | P0-B 设计 |
| **属性条件权限** | ABAC | 结合主体、资源、分类、时间和上下文的策略授权。 | 简单 RBAC 不必强行装成完整 ABAC。 | P1 安全 |
| **策略** | Policy | 由治理方发布的授权、风险或约束规则。 | P0-B 模型审查 Policy 与 P3 Action Policy 必须分层。 | 跨阶段 |
| **策略决策点** | `PDP` / `Policy Decision Point` | 根据主体、资源、操作和策略给出授权决策的服务。 | 不是仅存储一个 isAdmin 布尔值。 | 安全设计 |
| **策略执行点** | `PEP` / `Policy Enforcement Point` | 在 API、查询或 Action 边界实际拒绝越权请求的机制。 | 不能只在前端检查。 | 安全设计 |
| **行级安全** | `RLS` / `Row-Level Security` | 数据库层限定可访问数据行的纵深防御。 | 测试环境 RLS POC 不等于生产身份可信。 | P1 POC |
| **属性级授权** | Property-Level Authorization | 按 Property/Classification 限制查询、导出与派生计算。 | 有字段分类但无执行检查仍不能防泄漏。 | P1 规划 |
| **关系级授权** | Link Authorization | 对关联边是否可见和可遍历的权限。 | 能看见来源对象不等于能推断目标对象存在。 | P1 规划 |
| **撤权传播** | Revocation Propagation | 在查询、缓存、索引、导出和 Agent Context 中撤销已经取消的访问。 | 只阻止新 API 请求远远不够。 | P1 安全 |
| **派生数据权限** | Derived Data Label Propagation | 聚合、导出、Function 和 Agent 输出继承来源安全分类及保留规则。 | 行过滤不能保证所有派生物安全。 | P1/P2 |
| **审计** | Audit | 谁在何时对哪个稳定资源执行了何种读写和审批行为的记录。 | 简单日志不等于不可篡改审计。 | P0-B 设计 |
| **证据** | Evidence | 可追溯到来源、版本、主体、请求及结果的可验证材料。 | 审计证据不同于模型的 evidenceRequired 声明。 | 跨阶段 |
| **追踪** | `Trace` / `TraceId` | 把一次跨服务/任务的关联请求串起来的定位信息。 | Trace ID 本身不是业务事实证明。 | 工程 |
| **拒绝优先** | Fail Closed | 授权/来源/策略校验无法确定时拒绝高风险操作。 | 未知不应按允许继续。 | 跨阶段 |
| **最小权限** | Least Privilege | 主体只获得业务任务所需的最小资源与操作权限。 | 不能因内部 Worker 就默认拥有全部系统权力。 | 跨阶段 |
| **安全沙箱** | `Sandbox` / `Test Environment` | 与真实工业生产隔离的验证执行环境。 | CI 的模拟远端通过不表示工厂真实系统安全。 | P3/P4 |
| **数据保留** | Retention | 按治理政策保存或销毁有时限的来源与审计数据。 | 保留期到不允许破坏法定必留发布证据。 | P4 规划 |
| **可观察性** | Observability | 通过指标、日志、追踪和告警理解模型/查询/动作的运行行为。 | 有仪表盘不等于已经有故障恢复能力。 | 工程规划 |
| **恢复目标** | `RTO` / `RPO` | 恢复时间目标与恢复点目标，用于灾备和数据可接受损失约束。 | 尚未通过试点测量，不应写成产品 SLA。 | P4 规划 |

| **资源描述框架** | `RDF` / `Resource Description Framework` | 用主谓宾三元组表达资源关系的语义交换模型。 | Native 模型不要求全部变成 RDF 权威存储。 | P4 可选适配 |
| **Web 本体语言** | `OWL` / `Web Ontology Language` | 表达开放世界下类、属性、公理及推理语义的标准语言。 | 不是砺元核心业务执行与授权模型。 | P4 可选适配 |
| **语义查询语言** | SPARQL | 针对 RDF 图数据的标准查询语言。 | 不替代 Native ObjectSet typed query API。 | P4 可选适配 |
| **形状约束语言** | SHACL | 针对 RDF 图的节点/属性形状约束规则。 | 不能代替本体模型治理、发布审批和 Action Policy。 | P4 可选适配 |
| **国际化资源标识** | `IRI` / `Internationalized Resource Identifier` | 用于语义资源引用的国际化标识。 | Native 稳定 ID 默认不强制生成 HTTP IRI。 | P4 兼容 |
| **开放世界假设** | `OWA` / `Open-World Assumption` | 没有已知事实时，通常不能据此断言该事实为假。 | 不能因此放松企业业务数据完整性检查。 | 语义理论 |
| **封闭世界假设** | `CWA` / `Closed-World Assumption` | 在被限定且声明完整的业务数据范围内，可依赖受控规则处理缺失信息。 | 不等于所有来源都完整；PARTIAL 时不能未知即假。 | 运营语义 |
| **标准适配画像** | Interop Profile | 约定 Native 与 OWL/RDF/SHACL 等交换的有限支持子集。 | 不应声称所有标准语义均无损往返。 | P4 规划 |
| **迁移保真等级** | `LOSSLESS` / `PARTIAL` / `UNSUPPORTED` | 明确从旧 OWL-first 或外部语义到 Native 的转换保真程度。 | 不能静默丢掉 IRI、公理、域/范围或身份关系。 | P4 合同 |
| **国标本体研究** | `GB/T 48000.3` / `GB/T 48000.4` | 标准数字化与本体工程相关研究的借鉴参考。 | 参考条款不等于已通过国标符合性认证。 | 研究证据 |

## 在研发、UX 与用户帮助文档中的强制使用方式

- **UX**：新增页面、确认弹窗、警告和操作步骤，优先使用“推荐中文名称”；辅助说明用本表“不能混淆”列。对于未实现 P1/P2/P3，不显示已存在对象实例、可信审批人、生产 Action 的假数据。
- **设计提案**：新的 OFIP 第一次提及术语采用“推荐中文名称（Canonical English）”，公共合同引用 Native Schema 路径；发生同名不同义需提出新词条而非临时改写。
- **研发接口**：字段、类型和版本应引用真实 schema、Java record、TypeScript 类型；本表不是重命名脚本或开放 API 变更许可。
- **测试**：Golden Story 必须区分 `SchemaSnapshot` 与 `SchemaRelease`，`LinkType` 与 `LinkFact`；失败的查询应报告 UNKNOWN/PARTIAL/STALE 而非伪造空结果。
- **用户培训**：建议先讲 14 组区别，再用 `ProductionBatch → WorkOrder → CustomerOrder` 串起建模、来源映射、未来查询、受控行动，逐步展示哪些已具备、哪些尚待开发。
- **变更治理**：增加专业名词需填写中文标准名、英文/代码标识、定义、正例、反例、阶段和来源；如改变 API/Schema/权限/数据含义，应先经 OFIP 设计评审，再更新本词汇表；纯排版/解释修正可用普通文档 PR。
