# V0.1 → Native DSL/AST V0.2 迁移矩阵与拒绝策略

> **2026-10-15 · 设计评审候选，无自动迁移器。** V0.1 是 OWL-first 历史合同；V0.2 以企业运营本体 Native Schema 为权威。不能声称简单字段重命名就代表无损迁移、原审批继续有效或标准兼容性自动通过。

## 1. 类型与能力映射

| V0.1 资源 / 字段 | V0.2 对应 | 可转换条件 | 不成立时 |
|---|---|---|---|
| packageId、version、imports(packageId/version/digest) | Native Package + 版本锁 | 依赖版本和真实 Digest 已解析，签名和 Namespace 权限明确 | BLOCK |
| namespaceIri、类型的 iri、属性的 iri | External Semantic ID Mapping（可选 Adapter） | 持久映射表，来源 IRI 不丢失，IRI 所有权审查 | PARTIAL/UNSUPPORTED；不能静默删除 |
| EntityType | ObjectType | 显式 stableId 映射、apiName 兼容、可靠 PrimaryKeyRef、数据类型和工作空间归属 | BLOCK，人工补充主键/身份 |
| DataProperty | ObjectType.Property | Domain 唯一且合法、datatype 可映射、值域/required/枚举约束已等价表达；分类及可查询性明确 | PARTIAL 或 BLOCK |
| ObjectProperty | LinkType | Domain/Range、方向、Cardinality、证据来源、Stable ID 均明确；实际 LinkFacts 不从 Schema 推导 | PARTIAL 或 BLOCK |
| subclassOf | Interface/Inheritance Profile（后续） | 已有明确的 Native Profile 和兼容 Gate | UNSUPPORTED，不伪造继承 |
| equivalentClass、等价属性或同一性声明 | 语义适配器/人工审查候选 | 必须有经过验证的等价转换 Profile 和所有权同意 | UNSUPPORTED，不自动 owl:sameAs |
| DisjointClasses / 复杂 OWL Axiom | 专业语义 Profile | 保留原始 Axiom Artifact，签收推理能力与校验语义 | UNSUPPORTED；阻断声称无损迁移 |
| 复杂数据约束（regex、min/max、逻辑限制） | Native Constraint Profile 待扩展 | 编译目标有真正的同义校验及反例 | PARTIAL/UNSUPPORTED；不得悄悄删除 |
| Entity Fact / Relation Fact | P1 SourceFact / LinkFact Index | 来自已批准 Binding 与权威源的真实证据 | **不能从建模资产直接迁移出事实** |
| Action / Rule (V0.1 仅预留) | Rule/Function/Decision/Policy/Action | 增补版本、EffectScope、Policy、Approval、Executor、Idempotency 与业务核验 | 新建受审合同；不推断可执行权限 |

**说明**：LOSSLESS 指对于受支持的特定 Profile 保真，并不代表任意 OWL 本体可逆转换为 Native；PARTIAL 指部分意义未表达/被裁剪；UNSUPPORTED 指不具备保真映射。凡包含涉及业务授权或实例身份的不支持项，必须 BLOCK 自动迁移。

## 2. 不能悄悄处理的差异

V0.1 的 PrimaryKey 并非 EntityType 必填字段，V0.2 ObjectType 却要求它。不能靠第一个 required DataProperty、列名 id 或 apiName 猜测主键。真实身份必须由业务负责人选择/验证，并验证主键变更不会遗失已有编辑。

V0.1 使用节点 IRI 和已有下划线稳定 ID。V0.2 原生资源 ID 有新的格式约束；必须通过 MigrationManifest 显式记录 oldStableId → newStableId、oldIRI → optionalExternalIRI，不允许用字符替换下划线等方式暗中改动引用。

V0.1 有 DisjointClasses 等公理。迁移时如果没有批准的 Semantic Adapter/Profile，必须保留历史版本、报告 UNSUPPORTED，并阻止把输出标记为无损。OWL 的开放世界推理、SHACL 的数据质量校验、Native Policy 的执行授权也不能相互替代。

V0.2 新增 Data Binding、SourceAuthority、ObjectSet、Function/Decision/Policy/Action 的独立合同。这些资源没有 V0.1 一一对应产物时不能自动补出“可用来源”“已批准 Policy”“执行能力”。只允许生成待审 Draft，不允许自动 Active。

## 3. Migration Manifest（必须设计的中间交付）

正式 MigrationManifest 至少需要 sourcePackageRef/sourceDigest、targetDraftRef、MappingItems(oldStableId/oldIRI/newStableId/newType)、UnsupportedItems(reason/severity/originalArtifactRef)、SemanticProfile、CompatibilityReport、ConsumerImpact、Reviewer/Approver、ReviewDigest、执行批次与回滚引用。

一个 Release 的版本号变化不能替代保真验证。V0.1 旧审批绑定旧模型与旧语义，不得原样贴到 V0.2 Release。发布新模型时要重新校验真实 Consumer 的引用、权威来源、下游 ObjectSet/Function/Action 依赖，尤其不能让以前的批准扩大 Action 的 EffectScope。

## 4. 建议的 Gate 顺序

1. Inventory：读取 V0.1 全量 Schema 与依赖锁、枚举所有 IRI/公理/约束、评估来源实例使用情况。
2. Explicit Mapping：业务所有者批准 ObjectType、Property、LinkType 主键/域/值域和 External IRI 的目标映射。
3. Unsupported Report：列出每条公理、不能转换的约束与实际保真等级；不保真时默认拒绝无损发布。
4. Native Draft：只生成待审 V0.2 Draft，再经结构校验、Ref/Policy/Identity/Binding Gate 和兼容性 Diff。
5. Review/Approval：新的模型版本、迁移范围、消费者影响、摘要和回滚策略得到新审批。
6. Activation：真实对象索引/源映射必须分别激活与对账；不能因为 Schema 激活而断言所有源 Fact 已到齐。
7. Audit：记录已批准转换、拒绝项和证据，保证历史 V0.1 Package 和发布记录可追溯。

**当前项目只交付以上映射原则、Schema 与验证反例；未实现 MigrationManifest JSON Schema、转换引擎、语义 Profile 和生产迁移流程。** 实施前应作为独立 ADR 及迁移工作包评审。

## 5. 评审需要确定的决策

- Native primaryKeyRef 是否必须来自业务身份治理注册表，何种类型和变更可以安全升级。
- V0.1 IRI 与 V0.2 stable ID 的双向映射如何治理，如何处理旧链接与版本别名。
- 哪些 OWL 子集未来必须做到 LOSSLESS，哪些只需明确 PARTIAL/UNSUPPORTED。
- 正式迁移是否允许跨空间、跨依赖包的模型合并；失败后需要保留什么审计和回滚证据。

在这些决策被签收前，不应启动静默批量迁移，更不能将 OWL-first V0.1 的 Schema 直接拿来生成 P0 正式运行时。
