# OntoForge 精简版 MVP · 一条工业质量追溯纵向闭环

**2026-10-17 · PR 实施候选，未经人工 Windows 11 安装验收或生产签收。**

## 唯一黄金故事

1. 打开 Studio 菜单 **工业质量追溯 · MVP**；
2. 点击「创建示例本体」：真实调用 Native Draft / Save / Validate，生成三个 ObjectType（ProductionBatch / WorkOrder / CustomerOrder）、对应属性和两条 LinkType，状态必须为 VALID。已有包不覆盖；
3. 点击「绑定示例数据源」：使用 Flyway V4 中**隔离的合成 PostgreSQL 行**，持久保存模型对象 ID → 来源表及关系 FK 的白名单映射，锁定当前 draft revision；
4. 输入 `B2026-001` 点击「查询影响订单」：API 对真实 PostgreSQL 表进行参数化关联，从 B2026-001 → WO-1001 → ORD-9001，并返回来源表、字段和状态；
5. 修改真实 Draft 修订后，旧绑定失效，查询不能静默继续；再次保存/校验并重新绑定才可继续。

## MVP 非目标（本轮明确不做）

不做企业 SSO、复杂多角色、治理审核、SchemaRelease、Activation、跨包依赖、真实工业连接器、通用任意 SQL/通用 ObjectSet、Agent 平台、Action。保留既有建模/快照主线，不接入尚未批准的 B0 Draft PR。所有新的数据库对象使用 `mvp_` 前缀，不能混同真实业务来源。

## 明确的工程约束

- 后端监听默认 `127.0.0.1`；仅用于本地或隔离 CI。**禁止通过 S0_HOST 对公网暴露**，现阶段无生产身份安全保障；
- V4 为展示用途自动安装独立三张合成来源表和一张 demo-binding 表，不改 V1-V3，不自动读取用户真实 MES/ERP 表；
- 绑定是持久的，有实际源码配置对象/关系映射与 revision 限定；本轮查询仅允许预定义两跳关系，参数化 JDBC SQL 拒绝用户指定表/列；
- `B2026-001` 是被阻断的合成批次；`B2026-002` 是正常批次；结果来自数据库而非 HTML Mock；
- 现有手工建模页面继续存在；此引导只为降低第一次体验负担，绝不声称通用建模器已能自动绑定任意 PostgreSQL 表。

## 技术证据与验收门槛

`python -m unittest discover -s ontoforge-ui/e2e -p 'test_*.py' -v` 在真 PostgreSQL 17 + Spring Boot + Vite + Chromium 中完成：建模/校验、绑定持久化、双跳来源查询、未知批次 404、非法批次 400、修订变化后绑定失效 409、刷新后仍正确。原有 ObjectType、LinkType、Snapshot E2E 与服务重启回归必须全部继续通过。

**产品预期：** 用户只需三个步骤，不用看大量专业概念，即可看见 Ontology Language + Data Binding + 受控对象关系查询的最小价值。当前只是工业本体的价值验证，不是可上生产的完整平台。

## 2026-10-17 下一轮：可配置的本机 PostgreSQL 测试数据绑定（PR #33）

**核心变化只有一步**：第 02 步从固定三张内置表升级为可展开选择表与字段；第 01 步 Native 模型、第 03 步两跳查询和整套历史功能不重做。

1. **数据目录**：从**当前应用已连接的 PostgreSQL** 的 `public` schema 查询符合白名单的 BASE TABLE；首版只允许 `demo_`、`mvp_source_` 前缀和受支持的标量 ID/标签字段。真实表结构来自 `information_schema`，不允许提交任意 SQL、表/schema 路径和生产连接密码。
2. **映射内容**：批次表 + 批次 ID/状态/工单外键；工单表 + 工单 ID/订单外键；订单表 + 订单 ID/显示字段，合计十项。UI 为真实列下拉框，保存到 `mvp_demo_binding.source_map` JSONB，和 Draft 的 VALID revision 同时绑定，刷新后恢复。
3. **查询**：后端再次检查映射的表/列是否仍存在，转成严格限定的两个 JOIN 并用 JDBC 参数化批次 ID。对不存在的批次返回 404，来源变更拒绝查询，多条路径拒绝截断。
4. **兼容**：PR #32 已保存的旧 objectTypes/links 映射仍可读取为内置默认映射；不修改 Flyway V1–V4 历史表和 SchemaSnapshot，不添加新的企业治理。
5. **隔离测试**：CI 在临时数据库新建 `demo_quality_lots(lot_no,outcome,job_ref)`、`demo_prod_jobs(job_no,sales_ref)`、`demo_sales_orders(sales_no,buyer)`，浏览器选完十项后查到 `LOT-701 → JOB-77 → SO-88`；刷新保留映射、非法表/字段 422，原内置故事仍通过。

**本机试用提示**：仅对本机隔离 PostgreSQL **测试库** 中的 `public.demo_*`（或内置 `mvp_source_*`）表开放读取。创建自己的测试表后重启/刷新 Studio 菜单 **「工业质量追溯 · MVP」**，展开「选择 PostgreSQL 表与字段」后完成映射。不接受生产库、敏感字段或远程账号；无认证 S0 开发环境不可公网部署。

**MVP 实现层级**：实现的是单库、固定三种 ObjectType、两条 LinkType 的自选表字段绑定与读取，**不是**通用 Data Binding/多连接器、任意图遍历/完整 ObjectSet，也不是 Agent/Action。PR #33 的 CI 成功不替代 Windows 11 本地安装人工验收。
