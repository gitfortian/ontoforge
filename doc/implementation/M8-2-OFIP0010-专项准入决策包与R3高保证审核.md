## 3. P1 高保证实施前阻断问题及独立验收方法

### P1-01 · V10 非空 FK 事实与新 Bridge Revision 不能伪装成旧 FK

当前 V10 的 fk_owner / fk_source_column / referenced_identity_column 为 NOT NULL；**不能**把其中任意一个赋“BRIDGE”或假列名凑数。先在隔离已有历史 FK 的 PG17 上执行完整 Flyway V1→V10→下一版本，再断言：
- 老 revision 原字段、content_digest、old operation request_digest 与 receipt 字节保持不变；
- 新 Bridge Revision 的 FK-only 三列必须都为 NULL，Bridge 所需字段必须全非空，FK/Bridge 双态 CHECK 不允许混装；
- 历史 FK JSON 和历史 cursor 的模式判别不能被新默认值反向修改；
- 旧 revision immutable triggers 仍禁止 UPDATE/DELETE，新 revision 同样不可修改。

### P1-02 · 三表同一事务和真实 SELECT 资格

在一个 SourcePG Connection 上执行只读 REPEATABLE_READ，对三个受控 relation 当前 allowlist/schemaFingerprint/SELECT 独立核验；真实测试用另一个并发事务插入/删除 Bridge 或端点并验证同一读事务不会读取拼接混合状态。每次页面翻页重新验证 actor/package/snapshot/两端 M5 revision/Bridge table+columns。Bridge revoke 之后旧 cursor 410，即使重新授权也不会复活。禁止把 MetaDB 单事务宣称包含 SourcePG 数据变化。

### P1-03 · 预算是真实执行边界，不是对结果 LIMIT

必须在扫描/拼 Join 时控制总三表物理行、Join 中间候选与字节；用真实 EXPLAIN/ANALYZE、10k/10001、扇出/重复 pair、>8MiB、3s 超时构造证伪，不允许先 materialize 大 Join 然后只返回前 50。无法提供 FULL 的只返回 429/503 FAILED，无 objects/links/pathCount/aggregate/nextCursor。

### P1-04 · SOURCE/TARGET/BRIDGE 完整性与根局部质量

一次验证对 mutually exclusive 的 nullBoth/sourceOnlyNull/targetOnlyNull/sourceOrphan/targetOrphan/bothOrphan/matchedPhysical 求和必须等于 bridgePhysicalRows；matchedPhysicalRows - uniquePairCount 才形成重复行计数。不把不同 ObjectType 具有不同 identityDomain 误判非法；单字符串空值 != SQL NULL。OUT/IN root 分别计算局部孤儿，跨 root 污染视为 P1 失败。PARTIAL SUM 标已知子集，不把残缺总量当完整。

### P1-05 · 正式 React 必须真正复用产品 UX-High

对 [已签收 UX-High](../prototypes/m8-2-bridge-table-highfi.html) 的 H01–H12 建立生产 React golden story：入口→配置→FULL→CAS 保存→重开→OUT/IN→质量证据→授权撤销→错误与恢复，覆盖 375px、慢回包旧响应、UNKNOWN 重放；不能直接把 static HTML/Playwright 当作 M8.2 生产组件交付。
