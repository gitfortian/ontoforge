## 1. 30 秒产品交付结论

这轮交付**一个与 OntoForge 当前蓝灰色 Studio 视觉一致、可点击编辑的高保真原型**，统一承载对象类型、关系类型、保存与校验、历史与差异。它是未来真实产品的交互目标而不是已经开发的 React 服务。

本轮聚焦上轮审查提出的四类缺陷：

| UX-Low 发现 | UX-High 本轮采用的具体改动 | 用户可验证的效果 | 当前实现性质 |
| --- | --- | --- | --- |
| 只有简化对象属性，丢失专业字段 | 对象属性提供 **STRING / INTEGER / DECIMAL / BOOLEAN / DATETIME / ENUM**、ENUM 值、数据分类、必填、可搜索、业务标签与主键选择 | 产品专家能在同一工作台配置真实本体属性语义，而不是只能填写三个基础字段 | **Mock 可操作** |
| 删除被关联的业务对象容易丢关系 | 对象详情显示**被几条关系引用**，提供**直接查看关系**入口；删除时明确确认，保留悬空关系供用户修复 | 明确哪些关系会受影响，不能悄悄级联清理 | **Mock 可操作** |
| 技术 JSON Pointer 不易理解 | 校验问题显示“关系类型/对象类型 › 具体业务对象 › 问题属性”，同时保留技术路径便于研发定位 | 业务用户知道该进入哪个关系或对象修复，不需要理解数组下标 | **Mock 可操作** |
| 页面缺乏一致风格与步骤感 | 复用 0.3 Studio 风格的蓝色主动作、灰蓝导航、信息卡片、固定操作区和四步流程 | 用户知道下一步是对象→关系→保存检查→历史对比，菜单不新增“专业工具” | **Mock 设计** |

## 2. 页面交互：为何仍为一个工作台

```text
本体设计（主菜单）
 └ 模型包 > manufacturing.production
    ├ 对象类型
    │  ├ 对象选择、属性与主键完整配置
    │  ├ 被关系引用数量、影响提示
    │  └ 新增、删除及不丢编辑
    ├ 关系类型
    │  ├ 来源对象 → 目标对象及四类基数
    │  ├ 稳定 ID、显示名和未来证据要求
    │  └ 关系方向可视化，仅显示类型、没有实例
    ├ 保存与检查
    │  ├ 保存当前完整模型包修订
    │  ├ 只校验已保存同修订数据，定位错误
    │  └ 冲突、未确认保存与未知冻结结果恢复
    └ 历史与对比
       ├ 本地只读历史，非正式发布
       └ 同包两版的结构风险差异
```

**关键信息语义**：在用户操作流程中，草稿保存、模型完整性检查、本地历史留存与正式审核/发布分别呈现。原型只能展示前三者的交互模拟，**没有**真实审核人、Release、激活或 ERP/MES 写回；不能使用 Agent 或数据连接的假实例填充页面。

## 3. 黄金用户故事与异常路径

正常场景：进入制造示例，看到生产批次、生产工单、销售订单三个对象和“批次归属工单、工单关联订单”两条关系。点击对象检查完整属性表单；点击关系检查来源/目标与关联基数；保存→校验得到当前修订 VALID→留存本地历史→修改某条关系基数→再次保存校验留存→选择两版查看“潜在破坏风险”。

异常场景：删去被引用的 WorkOrder 时影响提示不能隐藏，关系保留但检查 INVALID；将主键属性类型改成 ENUM 时必须被标明不合法（主键只允许必填的 STRING / INTEGER）；ENUM 不填值应 INCOMPLETE；未知回执必须重新核对，修订冲突保留本地整个包而非当前行。

**本轮实际浏览器证据**：GitHub Actions [OFIP Prototype UX Browser Review #38883625997](https://github.com/gitfortian/ontoforge/actions/runs/38883625997) 对提交 `5238ab74cb1a3810061d03771710184297bd3584` 成功执行 **76/76 浏览器测试**，其中 **OFIP-0004 高保真 H01–H12 共 12/12 实际 Chromium 点击回归通过**。其余 64 项为 0.2/0.3 既有原型回归。本轮第一次测试确实发现一处测试脚本使用了错误的 JS 运算符，现已修复并经新运行复验为 PASS。该证据仅覆盖**内存静态 UI**，不包括真实 API / PostgreSQL / Windows 实机。

**浏览器测试的权限边界**：即使 H01–H12 全部通过，也只表明 Chromium 能实际操作**静态 HTML 内存原型**；未验证真实 React-Spring Boot API、Flyway PostgreSQL、快照持久化、Native release、权限或工业实例关系。正式工程验收继续依照 OFIP-0004 的 C01–C12。

## 5. 设计审查与未完成的专业能力

| 优先级 | 本轮设计审查判断 | 交给真实功能实现的验收要求 |

| P0 | 高保真 Mock 的字段校验只是用户交互参照，不可代替 Native Schema 机器合同 | Java Native Schema/跨对象引用校验与 UI 返回 path 一致 |

| P0 | 没有用户认证/权限/Release，不能对外开放或处理工厂生产数据 | 后续授权/审核发布需单独专业模块与安全门禁 |

| P1 | 技术路径可追溯，但业务优先提示还可进一步压缩 | 高保真签收后，真实 React 按业务实体和字段精确聚焦 |
| P1 | 移动端强调关键任务操作；工业建模以桌面为主要环境 | 实现时分辨率/窗口缩放下的内容可读性与触控可用性 |
