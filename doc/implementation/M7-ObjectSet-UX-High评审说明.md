## 本轮整改内容

根据独立深度审核，保留既有中性工业工作台布局，在原型层修复操作与结果不一致的问题：

- **筛选：** 采用 10 条合成 Supplier 数据；筛选会真实作用于模拟结果。字段类型决定允许的操作符，数值/布尔/字符串字面量会验证；IN 支持逗号分隔值。IS_NULL 只匹配实际 NULL，不把 MISSING 混同为空值。
- **排序：** 支持最多 3 个有序排序字段，方向可分别选择；重复字段不允许。NULL/MISSING 始终排在末尾，最终追加 ObjectRef 稳定打破平局。
- **投影：** 结果列由选中的投影属性动态生成；ObjectRef 始终保留。编辑查询后旧结果和状态徽标立即失效。
- **分页：** 按筛选与排序后的完整合成集合创建一次模拟结果快照。同一执行翻页保持快照标识不变；再次执行生成新标识。准确空结果与执行失败分开呈现。
- **聚合：** COUNT_DISTINCT 计算筛选后的不同 ObjectRef 数；SUM 根据选择的 DECIMAL 字段计算。聚合模式隐藏排序、投影和分页配置。SUM 输入含 NULL/MISSING 时失败关闭，不将缺失值默认视为 0。
- **授权与来源：** 增加“翻页时权限撤销”场景。后续页复核失败时返回模拟的 503 SOURCE_UNAVAILABLE，隐藏对象/聚合载荷，并明确标记旧快照失效；失败证据独立于成功结果区域。
- **证据与恢复：** 每次成功执行生成独立模拟快照标识；展示 Binding revision 和 freshness=UNKNOWN。失败保留错误代码、失败原因、恢复建议和复核结果，不伪造成功计数。准确零匹配显示为成功空结果。

## 视觉与交互决策

- 延续 OntoForge 中性工业工作台风格：低饱和蓝灰、明确边界、可扫描的信息层级。
- 保留左侧查询设计、右侧结果与证据；窄屏上下排列。
- 查询摘要动态呈现筛选、排序、投影、返回方式、Binding revision 和新鲜度，不显示与当前配置脱节的固定摘要。
- 分页与聚合互斥；聚合不显示与执行无关的排序/投影控件。
- 错误区域使用可访问的错误播报与焦点引导；恢复按钮明确返回查询设计。
- 原型仍明确标记为合成数据，不连接后端 API。

## Chromium 回归范围

本轮自动化扩展为以下行为断言：

1. 工作台打开、合成数据边界及 UNKNOWN 新鲜度。
2. 默认筛选实际排除 NULL 评级对象并显示准确计数。
3. 修改筛选值会改变匹配对象集合。
4. ASC 排序与动态投影真实影响结果行和列。
5. 最多三个排序字段及按属性类型过滤操作符。
6. 分页跨页保持同一结果快照；重新执行生成新快照。
7. 聚合与分页/排序/投影互斥；COUNT_DISTINCT 和 SUM 计算正确。
8. SUM 遇到 NULL/MISSING、无效数值字面量时失败关闭。
9. 预算、来源不可用、结构漂移、结果过期等失败场景不返回结果载荷。
10. 第一页成功后模拟翻页撤权：旧结果被隐藏并标记失效。
11. 准确空结果不是执行失败。
12. Binding revision 改变使旧结果失效、状态徽标复位。
13. 390px 窄屏无文档级横向溢出。

自动化通过仅证明上述**静态原型模拟行为**；它不证明服务端 AST、SQL、真实权限、来源预算、数据库并发一致性或生产数据快照已经实现。测试结果以 PR 最新 head 对应的 GitHub Actions 实际状态为准。
