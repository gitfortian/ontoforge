# M7 ObjectSet UX-High 原型评审说明

**状态：待产品所有者评审；未签收。**  
**范围：仅高保真静态交互原型，不包含生产查询运行时。**

原型：[`m7-objectset-highfi.html`](../prototypes/m7-objectset-highfi.html)  
前置 UX-Low：[PR #73（已合并）](https://github.com/gitfortian/ontoforge/pull/73)  
决策门禁：[OFIP-0009](../proposals/OFIP-0009-M7-通用ObjectSet查询.md)

## 本轮设计目标

把已签收的低保真流程转换为接近产品界面的视觉与交互方案：清晰的工作区层级、逐步配置查询、可读的查询摘要、独立的结果与证据区域，以及失败时可理解的恢复动作。

## 设计决策

- 延续 OntoForge 的中性工业工作台风格：低饱和蓝灰、明确边界、紧凑但可扫描的信息层级；不把原型做成独立品牌风格或营销 Demo。
- 页面固定分为左侧查询设计与右侧结果证据；窄屏改为上下排列。
- 通过编号步骤呈现对象/版本、筛选、排序、投影、返回方式、查询摘要。
- 执行结果明确标注为模拟成功，区分匹配数量、当前页、耗时、结果快照、Binding revision 和来源新鲜度。
- `freshness=UNKNOWN` 明确显示为未知，不宣称实时；对象身份、PRESENT/NULL/MISSING 和来源证据语义继续保留。
- 筛选最多 8 条；分页和聚合互斥；编辑查询清除旧结果；类型不兼容、预算超限、来源不可用、结构漂移、结果过期均使用失败关闭展示，不展示部分结果。
- 禁用尚未实现的 WorkOrder 选择，避免类型与 Binding/结果样例不一致。

## 原型与自动化边界

此 HTML 使用合成 Supplier 数据，不调用 API。Chromium 自动化验证页面可打开、核心步骤可见、查询模拟、分页、聚合、错误失败关闭、版本切换、编辑后结果失效和窄屏布局。测试通过仅证明原型行为，不证明服务端 AST、SQL、预算、授权或数据一致性已经实现。

## 产品所有者签收清单

1. 视觉层级是否符合 OntoForge 本体工作台，而非孤立 Demo？
2. 左侧逐步构建、右侧结果/证据的布局是否便于理解和持续操作？
3. 是否能区分对象数量、当前页、固定结果快照与来源新鲜度未知？
4. 错误状态是否说明发生了什么、是否返回数据、用户下一步怎么做？
5. 是否认可进入独立评审与后续原型修订？

## 后续门禁
