# OntoForge · MVP 功能全景、预期效果与实现成熟度

> **产品进度总账（2026-10-16）**。依据 [V1.3 总体架构](../本体产品总体功能与技术架构设计_v1.3.md)、[S0 迭代计划](./S0-MVP-迭代计划.md)、[PR #11](https://github.com/gitfortian/ontoforge/pull/11) 真实实现与审查记录。保留原 F01–F29 编号；P0/P1 的 MVP 范围及未来版本编号属于**建议，尚待产品评审**。
>
> **一眼结论**：0.3 不是“整个本体产品已经完善”，而是**模型历史版本留存、查看、结构比较这一个子场景的基础闭环，且关键异常测试已加固**。它仍没有正式发布/审批、真实工业数据、业务对象查询或 Agent 执行。本地 Windows 11 真重启验收未做；PR #11 已合并到开发主线（`9b0f802f`），**仍未正式发布**。0.4 关系子链路由 PR #13 单独交付。

## 1. 五条产品成熟度边界：必须说清哪个 MVP

| 范围 | 解决的真实问题 | 用户最终应看到的效果 | 当前状态 |
| --- | --- | --- | --- |
| **S0 工程基础 MVP** | 单人本地模型能保存、校验、留存历史吗？ | 建模工作台创建一个对象，校验后留存两份不可修改的版本并比较差异 | **0.3 已合并开发主线，Linux PG17/Java/React 自动化通过；Windows 本机与正式发布未完成** |
| **P0 专业建模 MVP** | 领域专家能否完整定义对象及关系，并可信审核发布？ | 建批次/订单/质量事件与关系 → 校验 → 审查 → 正式发布/读取/回退 | **尚未完成**；S0 只覆盖其一部分 |
| **P1 工业业务价值 MVP** | 能否跨真实业务系统查询对象与关系？ | 绑定受控 QMS/MES/ERP 测试数据，找出异常批次影响哪些订单及依据 | **未实现产品**；部分查询研究 POC 不能计入 |
| **P2 Agent 增强 MVP** | Agent 能否读到有权限、有证据、可追溯的真实业务上下文？ | Agent 通过 SDK/MCP 只读查询批次、工单和影响订单，并引用来源和数据时效 | **未实现** |
| **P3 受控行动 MVP** | 审核后能否安全处置，并确认外部系统真实结果？ | 展示操作计划 → 权限/审批 → 沙箱调用 → 回执/未知态/结果核验 | **未实现**；Outbox 研究实验不算交付 |

P0 是**建模产品可用门槛**，P1 才是**工业业务价值开始成立的门槛**；P2/P3 是后续能力。不能把当前 S0 版本称为面向工厂可用的工业本体平台。

## 2. “最基础”与“完善”的判定口径

| 层级 | 如何判定 | 报告中的表述 |
| --- | --- | --- |
| 未实现 | 只有想法、需求或架构草案，无真实用户功能 | 未实现 |
| 研究验证 | 有 Schema 合同、实验代码、Mock 原型，但未接通真实产品流程 | 已研究/已验证部分风险，**不是功能完成** |
| **基础可用** | 在有限范围内完成真实页面/接口/数据保存与关键错误路径 | 基础可用，说明**具体子功能** |
| **基础可用·加固** | 在基础场景上验证过并发、异常、完整性等高风险边界 | 该子场景可靠性加固，**不是全域完善** |
| **专业完善** | 对象、关系、权限、依赖、审查、发布、业务异常等核心场景均打通 | 专业功能较完整，仍需正式环境验收 |
| 生产验收 | 完成身份/数据安全/运维/规模/故障恢复等实际环境验证 | 在限定部署边界内可试点/上线 |

**两轴原则**：功能覆盖范围和技术可靠性单独报告。比如 0.3 的历史快照可靠性好，但 F04「版本发布」的正式审批、发行和激活仍为**未实现**，不得将 F04 标为完成。不得凭通过测试的数量推算全局完成百分比。

## 4. P0「完整建模产品 MVP」建议功能包

> 下列是**接下来要评审的 P0 候选最小清单**，不代表已批准排期。MVP 可以聚焦，但不能为了“最小”牺牲安全和发布语义。

| 产品功能 | 对应全局功能 | 完成后用户实际看到的结果 | 当前实现深度 |
| --- | --- | --- | --- |
| 可信进入工作区 | F01 / F19 | 按身份打开自己的空间，跨空间无权限时被拒绝 | **未实现** |
| 创建与复用模型包 | F05 | 新建包，管理模型包依赖及已锁定版本 | **仅基础模型包** |
| 对象/属性建模 | F02 | 创建批次、订单、质量事件并定义属性、主键 | **单个 ObjectType 表单基础可用** |
| 对象之间的关系建模 | F02 | 定义生产批次—工单—订单的 LinkType，可重新打开修改 | **未实现** |
| 完整性与语义校验 | F03 / F28 | 明确显示错误位置、关系及引用不一致和修复路径 | **仅基础字段校验** |
| 模型历史、对比 | F04 | 可保存历史，两版差异及风险可复查 | **0.3 基础加固子项** |
| 变更审查与退回 | F25 / F20 | 能看到提交人、变更范围、审核意见及退回原因 | **未实现** |
| 可信发布/读取/回滚 | F04 / F19 | 通过审批产生独立正式版本，历史永久保留，失败不激活 | **未实现** |
| 依赖影响与兼容检查 | F05 / F28 | 修改主键/关系前看到影响哪些依赖/消费者 | **仅结构风险提示** |

**P0 产品验收故事**：建立生产批次、质量事件、订单三类对象 → 建立 LinkType → 校验 → 提交审查 → 可信发布 → 按版本打开与受控回退。当前还只能完成这个故事的**部分对象定义/检查/历史留存**。

| **P2 Agent 只读增强** | Agent 读取某批次及受影响订单、引用来源和版本、说明数据时效 | 没有权限的对象不可访问，模型/事实版本可回证 | 未开始 |
| **P3 审批后受控行动** | 用户批准复检任务，在业务系统沙箱执行，观察业务结果/未知态 | 策略/审批/外部回执/状态核验/失败恢复 | 未开始 |

**优先级建议**：不要为了全景图把 29 项同时开发。先收口 0.3，下一轮评审关系建模与可信发布，再用 **一条真实工业查询黄金故事**验证产品价值。0.4 的功能名称和版本承诺在产品评审完成前不冻结。

## 7. 一条工业黄金故事：全局进度的校准尺

**问题**：QMS 检测到一批物料质量异常，质量工程师希望知道影响哪些订单，并有据可查。

| 过程 | 用户应该能操作的真实结果 | 目前距离 |
| --- | --- | --- |
| 设计语义（P0） | 创建批次、质量事件、工单、订单对象和关系 | **仅部分对象/属性及历史留存** |
| 审查发布（P0） | 经过可信人员审查、发布受控版本 | **未实现** |
| 绑定来源（P1） | 将 QMS、MES、ERP 事实映射到对象及关系，显示来源 | **未实现** |
| 影响查询（P1） | 输入异常批次，看到受影响订单、路径与数据更新时间 | **未实现** |
| Agent 分析（P2） | Agent 只读总结订单影响并引用可追踪来源 | **未实现** |
| 受控处置（P3） | 经审批发起复检或冻结，在原系统核验结果 | **未实现** |

0.3 是前两步里的一个必要基础能力，但**距离真实工业业务价值仍有清楚的缺口**。每轮 PR 都要标注它推进了上面哪一个步骤，而不能只报告提交了多少类和多少测试。

## 8. 以后如何把每个 PR 自动映射到全局功能

每轮交付必须新增一张「**本轮 → 全局功能对照表**」，包含：全局 F 编号、子功能、原成熟度 → 新成熟度、用户入口/实际效果、本轮是新增功能还是测试加固、尚缺的同域功能、验证/签收证据、接下来应实现哪项。**只补测试不能直接提高功能覆盖率；只能提高已有子项可靠性。** 不允许把样例/POC 算作正式产品。

维护建议：本文件是**功能总账**；[交付说明模板](./交付说明模板.md) 是每轮变更记录；[0.3 本轮产品交付说明](./S0-MVP-0.3-交付说明-20261016.md) 是实例；技术错误码和真实验收细目继续保留于 [0.3 Review 验收矩阵](./S0-MVP-0.3-功能说明与全面Review验收矩阵.md)。最终产品定义权威仍是 V1.3 和通过评审的 OFIP。

**当前建议结论**：S0.3 是局部基础闭环（可靠性加固），不是「F04 版本发布完善」，也不是「OntoForge 工业本体 MVP 已完成」。产品全景先校准清楚，再继续新阶段。
