# OntoForge 精简 MVP：脱敏工业测试 CSV 接入

本轮只解决一件事：**让已有的批次 → 工单 → 订单追溯页面使用用户自备的脱敏测试记录**。本脚本独立于 B0 Draft PR #17，不触及生产 MES/ERP。

## 操作流程

先创建一个与业务库严格隔离的本机 PostgreSQL 数据库，例如 `ontoforge_test_quality`，将自己的**脱敏**测试样例整理为以下 UTF-8 CSV（示例见 `scripts/mvp-quality-csv`）：

| 文件名 | CSV 表头 | 含义 |
| --- | --- | --- |
| `sales_orders.csv` | `sales_no,buyer` | 订单 ID、展示名称 |
| `prod_jobs.csv` | `job_no,sales_ref` | 工单 ID、关联订单 |
| `quality_lots.csv` | `lot_no,outcome,job_ref` | 批次 ID、质量状态、关联工单 |

Windows 11 PowerShell 5.1 示例（要求 PostgreSQL `psql` 在 PATH 中，或通过 `-Psql` 指明可执行文件；使用数据库认证环境变量或本地 `.pgpass`）：

```powershell
.\scripts\import-quality-test-data.ps1 -Database ontoforge_test_quality -DbUser postgres -CsvDirectory .\scripts\mvp-quality-csv
```

导入后，在本地开发启动前将 OntoForge 的 `DB_URL` 指向同一个隔离库。进入左侧 **工业质量追溯 · MVP**，第 1 步创建模型，第 2 步选择并预览对应来源字段：

- `demo_quality_lots`：`lot_no`, `outcome`, `job_ref`
- `demo_prod_jobs`：`job_no`, `sales_ref`
- `demo_sales_orders`：`sales_no`, `buyer`

保存绑定后，第 3 步输入 `LOT-701`，示例应查到 `JOB-77 → SO-88`。替换 CSV 为真正脱敏的样例后，输入你自己的批次编号。

## 不越界的保护

脚本仅允许 `localhost/127.0.0.1` 和名字匹配 `ontoforge_test_*` 的数据库，不接受任意 SQL/表名/远程服务器；拒绝错表头、重复主键、断链外键、空字段或超过 10,000 行/表。固定表名为 `public.demo_*`，三张表的导入在一笔 PostgreSQL 事务内。

**重跑将覆盖该测试库三张 `demo_*` 表的旧数据**。数据库名字保护不是生产数据防护的充分条件：务必确认实际连接到了你新建的测试数据库，不要把生产库冒充测试库。仅使用脱敏数据，当前本地服务不具备正式生产安全能力。

本轮不建设通用连接器、数据同步、ObjectSet 引擎或 Agent；也没有接入用户真实工业系统。正式产线数据的任何处理需另行安全与授权评审。

## 验收

CI 需要在真实隔离 PostgreSQL 17 连续导入两次，检查行数无重复、跨表能追溯到订单，并检验不允许指向名为 `production` 的数据库；另有 Windows PowerShell 5.1 原生语法门禁。人工 Windows 11 环境的安装与数据核对仍独立待验收。
