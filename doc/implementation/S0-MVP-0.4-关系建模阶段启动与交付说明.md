## 四、业务黄金故事：如何判断这一轮的未来代码有没有做完整

**目标演示**：进入模型包 → 新增生产批次、生产工单、销售订单 → 为每类对象定义主键 → 新增“批次关联工单”和“工单关联订单”两条关系 → 保存并校验 → 冻结当前本地快照 → 修改其中一条关系的基数 → 再保存、校验、冻结 → 选两版比较 → 看见关系变化风险。

**必须能验证的反例**：端点对象不存在、同名关系标识、关系基数非法、删除被关联对象、旧修订覆盖、未保存退出、超时后按原请求核对、历史快照不被新定义覆盖、含尚不支持 Binding/Action 的草稿不能被静默裁剪。

**范围边界**：不是实时 MES/ERP 接源，不是对象实例/关系事实，不是正式审核发布，不是企业权限，不是 Agent/工业 Action。
