## 3. 真实测试级别与数据一致性边界

1. **质量通过不等于发布**。上一轮可核实 HEAD `e6e18927afab745d1fe1efc7c3a2e2fac57af3f9` 的三组 Actions completed/success：[S0](https://github.com/gitfortian/ontoforge/actions/runs/39232104069)、[Docs](https://github.com/gitfortian/ontoforge/actions/runs/39232103943)、[Required Quality](https://github.com/gitfortian/ontoforge/actions/runs/39232104085)。**本文件与并发压力测试之后的新 HEAD 必须重跑三组，不能继承上述结果。**
2. **并发缓存范围**：事务内原子检查的是已冻结 JSON **16 MiB / 32 slots**，不能证明 JDBC 行对象、构建中 JsonNode、JVM 堆及所有并行 Worker 的峰值内存；故如需生产级硬内存上限，应另设运行时总并发准入/heap profile 验收，不能使用“已经完全解决 OOM”表述。
3. **来源一致性**：M8 从白名单 PostgreSQL 同一只读 REPEATABLE_READ 事务读 SOURCE/TARGET；它与元数据写入事务并非同一个外部事实事务，`sourceReadRefs` 和结构指纹保留此边界。
4. **EXPLAIN 证据**：9,802 个关联的 PG 计划验证 SQL 查询，不代表端到端 Java Join 在所有硬件/并发下始终小于 3s；服务端真实请求包含 deadline 检查和 429/503 fail-closed。
5. **Windows 11 用户本机 PostgreSQL UAT：NOT RUN**。CI 的 Windows PowerShell 5.1 parser 只能证明脚本语法，不能替代本机数据库、账号 Session、Source grant、Flyway V10 真实升级验证。
