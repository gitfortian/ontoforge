## Motivation

领域工程师应能在自己创建的模型包中定义对象及关系、绑定隔离 PostgreSQL 测试事实、查询对象集合并解释来源，不再切换到固定制造模型才能运行。
例如用户创建“样品—检验任务—报告”三个自定义类型，绑定三张自备表，筛选未通过样品，沿关系找到关联报告，并从报告返回查询步骤和来源依据。
成功必须由新类型、字段和数据完成；换掉固定制造页面上的文字不是通用工作台。

基线审阅为 `6968ea0804f57b2b82f237e37f812bcadb32f343`：

- [main.tsx](../../ontoforge-ui/src/main.tsx) 已有 hash 导航、全局未保存保护和运行身份提示。
- [NativeModelWorkspace.tsx](../../ontoforge-ui/src/NativeModelWorkspace.tsx) 已有真实草稿编辑、校验、版本冲突和异步请求失效保护；[NativeSnapshotWorkspace.tsx](../../ontoforge-ui/src/NativeSnapshotWorkspace.tsx) 提供本地快照。
- [QualityMvpWorkspace.tsx](../../ontoforge-ui/src/QualityMvpWorkspace.tsx) 与 [QualityMvpController.java](../../ontoforge-boot/src/main/java/io/ontoforge/boot/controller/QualityMvpController.java) 已实现 M2/M3 有限集合、分页和来源映射，仍围绕三个固定 Native 类型。
- `mvp-local` 是显式 opt-in 本机无认证路径；非本机 Profile 已有 JWT 及数据库包授权代码。二者都不能被工作台文案追认为生产安全验收；yak-ops HttpSession 只是未来复用方向。

Issue 的方向合理，但 M11 不能成为 M5–M9 第一次交付用户 UI 的阶段。
此前每个功能仍交付自己的前后端纵向闭环；M11 收口这些已验收能力的连续体验、上下文一致性和跨领域复用。
前置是 M5–M9 所需合同及可用能力；M10 仅是正式发行入口的前置，不阻塞本机核心流程。

非目标：新建第二套前端应用、全新 UI 组件库、任意 SQL 编辑器、全功能图谱画布、连接器市场、生产权限管理或 Action 页面。
工作台不替代查询、Binding、身份、版本和证据的领域规则，也不通过前端补齐尚不存在的服务能力。

## Public Interfaces

### 工作上下文与路由

工作台使用候选 `StudioContext v1` 描述导航，不作为新的领域真相源：

| 字段 | 含义及所有权 |
| --- | --- |
| `packageId` | 当前模型包；服务端对包及目标资源逐请求核验 |
| `typeRef` | `{sourceRef, objectTypeId}`；`sourceRef` 为 `LOCAL_SNAPSHOT(snapshotId)` 或 `VALIDATED_DRAFT(draftId, revision)` |
| `bindingRef={bindingId,revision}` | 所选已保存 Binding 的精确修订；持久绑定首版仅允许 Local Snapshot |
| `executionId` / `queryDigest` | 本次临时查询及有界结果身份；TTL 5 分钟、重启失效，不是持久 ObjectSetDefinition |
| `objectRef` / `evidenceRef` | 服务端返回的对象身份及证据引用；前端不得从显示名称推导 |

浏览草稿、历史快照和运行结果是不同视图，页面持续显示实际版本来源。
`SCHEMA_RELEASE(releaseId)` sourceRef 仅能在 M10/OFIP-0005 新合同被接受并实施后显式加入；Local Snapshot 不能显示为 SchemaRelease。
URL 只保存可核验资源引用及允许的视图信息，不保存连接密码、原始 SQL、令牌、敏感筛选值或整份结果。
刷新/分享链接重新加载并授权，链接本身不授予访问权；临时查询无法恢复、已过期或重启失效时明确提示重新执行。
M7 首版不支持持久查询定义；保存/分享查询需要后续合同，工作台不能自行增加持久 ObjectSetDefinition。

### 运行结果和错误

查询响应沿用 M7–M9 接受后的版本、分页、预算及 Result Evidence 合同，UI 不再包装成“查询成功=true”。
执行绑定引用统一为 `{kind,bindingId,revision,digest,sourceId}`，kind 区分 OBJECT/LINK；不把本机 revision 伪装成 SemVer。
状态至少区分加载、空结果、完整结果、部分结果、来源过期、权限拒绝、版本失效、运行失败；未知状态显示不可判定并停止后续操作。
版本、来源水位、完整性、精度及失效原因是独立维度，不能合并为一个绿色徽标。

| 错误类别 | 用户可继续的操作 |
| --- | --- |
| 草稿 CAS 冲突 | 保留本地编辑，读取最新 revision，比较后显式重做；禁止自动覆盖 |
| Binding/模型版本变化 | 清除旧分页与当前运行资格，查看差异并重新选择/复核 |
| 来源漂移/不可用 | 显示当前失败及上次结果的时间，去 Binding 复核；旧结果不能冒充本次运行 |
| 401/403 或资源不可见 | 停止请求、清除可见结果及缓存，不回显被拒资源的名称或统计 |
| 超时/预算超限 | 展示失败原因、缩小条件与重跑入口；不展示“0 个对象” |

本提案不新增独立数据库业务实体或查询语法；确需补充的工作台资源组合接口须在实现 PR 中列出消费者及受影响合同。
后端是权限、引用解析和版本判断的唯一权威，按钮可用性只是对服务端结果的呈现。

## Proposed Changes

### 1. 一条连续用户流程

1. 从模型包列表打开已有包或新建自己的包，完成类型/属性/LinkType 编辑；未完成草稿可以保存，但不能运行查询。
2. 校验具体 revision；有效后创建/选择 Local Snapshot。用户明确知道自己查看的是草稿还是不可变历史。
3. 在当前类型上下文进入 Binding，选择允许的本机测试来源，映射主键、属性及关系，预览并保存；预览和持久绑定的版本分开显示。
4. 从该 Binding 打开对象浏览；类型、可筛选属性和关系来自实际合同，不使用硬编码制造 ID。
5. 进入 ObjectSet 查询，配置已实现的过滤、遍历及聚合，显示步骤的输入/输出类型和预算；服务端校验后才执行。
6. 从结果打开对象、关系路径及最小来源证据，再返回同一查询及页位置；证据链接不默默跳到最新 Binding。
7. 用户切换模型/Binding 或重新执行时，当前界面清除旧游标并开始新执行；旧执行如仍满足 TTL/授权/来源结构条件，可查看其原冻结结果，不能和新结果拼接。

不存在的操作不生成假按钮或成功通知。M10 未实施时只提供真实本地快照能力；本机模式不显示虚构登录人或审批身份。
当前固定质量追溯入口作为有明确范围的演示保留，不能作为自定义领域验收的替代品。

### 2. 导航和请求一致性

所有包/版本/Binding/查询切换、后退前进及退出使用统一未保存保护。
草稿保存响应丢失时先重新读取服务端 revision 核对，保留本地输入；不得把网络异常当成保存失败后直接重发覆盖。
Local Snapshot 为只读；编辑行为创建/打开可编辑草稿，不能直接改历史快照。

请求的有效性键至少包含当前包、typeRef、完整 Binding 修订集合、查询摘要和身份会话代次。
切换上下文、撤权、重新运行后取消旧请求并使旧响应失效；A 包的慢响应不能覆盖 B 包屏幕。
分页游标必须来自当前查询执行；更换排序、筛选、版本或 Binding 后丢弃旧游标。
M7 在一次有界执行内物化 resultSnapshotRef，后续页读取同一冻结成员、值、排序与计数；普通源 DML 不重算旧页，新 execution 才反映新事实。
TTL/重启、撤权、依赖结构漂移令结果失效；来源断开/检查失败按 M9 fail-closed，不能声称前端分页创造了源 MVCC 历史。

### 3. 信息架构与原型 Gate

采用当前单一 `ontoforge-ui` 应用，围绕包内“模型、Binding、对象与查询、证据”安排导航。
领域类型和属性名是内容，工作台控件来自受支持的通用类型/查询能力；不能按某一行业生成新组件分支。
先复用已存在的编辑器和服务，只有观察到同一责任重复才提取公共组件。
错误提示可定位字段或步骤，并明确下一步；通过键盘完成主要任务，焦点、表单标签、状态播报和对比度纳入验收。

重大交互实施前保留 Issue 原有 Gate：需求/边界评审 → 低保真任务流 → 高保真原型 → 维护者与目标用户明确签收。
原型至少包括首次空状态、保存冲突、来源漂移、部分结果、版本切换和无权限；签收记录不替代真实代码验收。
本次仅提交正式设计讨论，不把上述原型标记为已完成。

### 4. 交付与责任

M5–M9 各自负责人继续拥有对应用户闭环及领域合同，M11 负责人拥有跨页面任务流和状态一致性。
M11 首个实现 PR 交付上述自定义领域从包到证据的连续路径，复用已验收能力；不顺带实现缺失的连接器、查询算子或发布系统。
若依赖尚未完成，先明确阻断项并拆出可验收任务，不能用占位服务和假数据宣布工作台完成。
低高保真评审、两领域复核、错误恢复和既有路径回归都通过后，再记录 M11 用户验收。

## Compatibility, Deprecation, and Migration Plan

- 保持既有 `/api/model/drafts`、快照、`/api/mvp/quality` 和当前 hash 深链接可用；改路由提供确定性兼容跳转及回归，不能破坏未保存保护。
- 本提案不更改 `editorSchemaVersion=0.1.0`、Native V0.2 候选 Schema 或快照 JCS/SHA-256 规则，不将前端状态保存为新模型格式。
- 旧制造 Binding 不能只改标题就转换成通用 Binding；沿用原入口，按 M5–M9 的显式迁移/拒绝规则建立新资源。
- 仅视图偏好可本机保存，禁止在 localStorage/sessionStorage 新增业务结果、来源凭据或访问令牌缓存。
- 原有 Flyway V1–V6 不改；纯 UI 整合默认无迁移，未来确需持久视图偏好则用实施时下一个未占用版本单独评审。
- JWT 路径保留签名/issuer/audience/包权限负例；本机核心验收无需 IdP。未来 HttpSession 复用需独立身份/会话/CSRF 设计，不由本提案实施。
- 回滚工作台应保留领域资源和旧入口；不能通过回滚 UI 恢复已撤销权限、撤销已产生模型修订或删除证据。

## Rejected Alternatives

1. **M5–M9 只交后端，M11 一次补齐 UI**：无法逐阶段验证用户价值，且整合问题会掩盖领域合同错误；每个 M 仍需纵向交付。
2. **在固定质量页面继续加对象类型 if/else**：不能证明任意用户定义类型可用，且易把制造字段当成模型合同；通过合同生成内容并用独立领域验证。
3. **一次替换整个前端或先建立共享组件库**：没有新的消费者与独立交付价值；复用现有单应用，仅提取已出现的共同责任。
4. **用统一“成功/失败”状态简化所有页面**：会隐藏部分结果、来源过期和未知保存结果；保留领域状态并提供恢复操作。
5. **要求先完成企业登录与正式发行才能使用核心工作台**：与已记录的本机核心优先决策不符；正式共享访问仍需独立安全 Gate。
