## 1. Motivation

### 用户目标

领域专家在已有 Native 工作台创建模型包 procurement.core、ObjectType Supplier 与 PurchaseOrder（包含主键、属性、类型、约束），保存并校验 VALID 后，无需新增 Java 业务 Controller、业务枚举、特定工业场景 SQL，即可在统一界面查看两种类型的**运行时定义**和明确的版本来源。

M4 的完成定义是“类型可被通用运行时理解和引用”，而非“已有供应商实例可查询”。实例源事实由 M5 Data Binding / M6 Object Runtime 提供；ObjectSet 查询由 M7 提供。

### 已核实 AS-IS

- NativeDraftService：持久化 Editor JSON v0.1 editing_document、revision、ValidationReport；并发保存采用 revision CAS，成功保存后使旧 validation 失效；**不持久化 Native Candidate**。
- DraftValidation.validate(packageId, editingContent, mapper)：重新生成 Native V0.2 Candidate，规范化空 label、非 ENUM enumValues，补齐受限资源空数组。当前 Candidate 的 version 固定为 0.1.0，不能充当运行时不可变版本。
- NativeSnapshotService.get：读取已冻结本地快照时进行 JCS 字节、SHA-256（64 位小写裸十六进制）、JSONB 镜像及 Native Schema 核验；lifecycle=LOCAL_SNAPSHOT_ONLY。
- SecurityConfig 与 LocalMvpSecurityConfig：现有 /api/model/** 已受控制，原计划 /api/runtime/** 不在 allowlist，将被默认 denyAll。
- B0AuthorizationService：READ_DRAFT 和 READ_SNAPSHOT 当前授权角色仅为 EDITOR、REVIEWER、PUBLISHER、OWNER，**不包括 VIEWER**；M4 不修改既有 RBAC。
- DraftValidation.checkEditor：每个模型包最多 50 个 ObjectType，单类型最多 100 个 Property；M4 单包目录不需要游标分页。
- NativeModelWorkspace 已具备编辑对象类型的选择列表；M4 不应复制第二套编辑器。

### 非目标

不做新的登录/鉴权、物理 Registry 表、数据绑定、ObjectFact、实例 CRUD、LinkFact、自由 SQL、ObjectSet AST、正式 Release/Activation、Agent/Action、跨包聚合目录。

## 2. Public Interfaces

### 2.1 类型身份：TypeSourceRef 是互斥判别联合

**DRAFT（临时，仅本地建模预览）**

~~~json
{
  "kind": "VALIDATED_DRAFT",
  "draftId": "<UUID>",
  "revision": 3
}
~~~

**SNAPSHOT（不可变本地开发版本）**

~~~json
{
  "kind": "LOCAL_SNAPSHOT",
  "snapshotId": "<UUID>"
}
~~~

TypeRef = (TypeSourceRef, objectTypeId)，其中 objectTypeId 必须是 Native ObjectType.id（稳定 ID），不是 apiName/display label。packageId 由服务端从源记录推导并在响应中返回；不接受调用方伪造的包归属、主体与授权上下文。**不支持隐式 latest。**

- DraftRef 的 revision 是瞬时验证条件，后续保存会使其失效；不能暗示是持久版本。
- SnapshotRef 指向特定 snapshotId；服务端核验存储摘要，结果可返回 payloadSha256 的 **64 位裸十六进制字符串**。这与 Native Schema 中部分 digest 字段要求 sha256: 前缀的格式不同，不混用。
- M5 默认选择 Local Snapshot 作为持久化 Binding 的模型来源。若未来另行批准临时 Draft Binding，必须锁定 draftId+revision，变更后标记失效、禁止暗中迁移。

### 2.2 API（候选，位于已存在的 /api/model/** 安全域内）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/model/type-sources/drafts/{draftId}/types?revision=3 | 取指定 VALID 当前草稿的类型摘要 |
| GET | /api/model/type-sources/drafts/{draftId}/types/{objectTypeId}?revision=3 | 取草稿类型详情 |
| GET | /api/model/type-sources/snapshots/{snapshotId}/types | 取本地快照类型摘要 |
| GET | /api/model/type-sources/snapshots/{snapshotId}/types/{objectTypeId} | 取快照类型详情 |

- 列表响应为 items[]，每包最多 50 个，按 objectTypeId 升序，**不包含 pageSize/cursor**。不支持跨包聚合与原地筛选。
- 列表仅提供 objectTypeId、apiName、label（可选）、primaryKeyRef、propertyCount；详情再返回全量 PropertyDescriptor。
- 详情结构包含 sourceRef、packageId、modelSourceRevision、lifecycle、objectTypeId、apiName、label?、primaryKeyRef、properties[]；Snapshot 来源时提供 payloadSha256。
- PropertyDescriptor 必须携带稳定 id、apiName、label?、valueType、required、searchable、classification、enumValues?。属性类型只取 Native V0.2 的 STRING/INTEGER/DECIMAL/BOOLEAN/DATETIME/ENUM；当前 PK 规则为 required 且 STRING/INTEGER。**主键存在不推导 searchable=true**。
- **禁止**返回对象实例、来源表列、绑定“已就绪”、正式 Release/Active 状态。无需虚构 bindingState 字段。

示意响应（仅草稿类型列表，所有 UUID 均为示意；不得作为真实证据）：

~~~json
{
  "sourceRef": {"kind":"VALIDATED_DRAFT","draftId":"11111111-1111-4111-8111-111111111111","revision":3},
  "packageId": "procurement.core",
  "modelSourceRevision": 3,
  "lifecycle": "VALIDATED_DRAFT_ONLY",
  "items": [
    {"objectTypeId":"purchase-order-type","apiName":"PurchaseOrder","primaryKeyRef":"order-id","propertyCount":2},
    {"objectTypeId":"supplier-type","apiName":"Supplier","label":"供应商","primaryKeyRef":"supplier-id","propertyCount":3}
  ]
}
~~~

### 2.3 状态码（候选）

| HTTP | Code / 行为 | 用户恢复 |
|---|---|---|
| 400 | MALFORMED_TYPE_REF（错误 revision/非法 ID 等） | 检查来源或参数 |
| 401 | AUTHENTICATION_REQUIRED（非本机 JWT 模式无身份） | 登录 |
| 403 | ACCESS_DENIED（现有包授权拒绝） | 获取授权；不泄漏内容 |
| 404 | TYPE_SOURCE_NOT_FOUND / OBJECT_TYPE_NOT_FOUND（通过安全边界后未找到） | 核对来源或类型 |
| 409 | TYPE_SOURCE_REVISION_CONFLICT（请求版本不是当前版本） | 重新读取并校验 |
| 409 | TYPE_SOURCE_NOT_VALIDATED（NOT_RUN/INVALID/INCOMPLETE） | 修正模型、重新校验 |
| 422 | UNSUPPORTED_TYPE_DEFINITION（无法安全规范化） | 回到建模校验报告 |
| 500 | SNAPSHOT_INTEGRITY_FAILURE（复用现有快照完整性语义） | 阻止继续，核查存储 |
| 503 | PERSISTENCE_UNAVAILABLE | 恢复 PG 并重新读取 |

不存在的资源、未授权资源如何区分必须与现有 401/403/404 行为一致；不能宣称统一返回 404 反枚举，除非未来另行改变现有授权契约。由新 Controller 显式接入已存在的安全异常处理/一致错误响应；目前 DraftErrorAdvice 仅覆盖既有三个 Controller，不能假设自动覆盖新接口。

## 3. Proposed Changes

### 3.1 Resolver 权威转换与一致性

Draft 读取步骤：

1. 控制器使用 requireDraft(READ_DRAFT)，遵守非本机身份与包授权；本机模式仅用于 loopback + 独立脱敏测试库。
2. 从同一条 PG SELECT 结果获取 packageId、editingContent、revision、validation.status、validatedRevision，使用这一行作为读取线性化点，不混合多个修订；请求 revision 与读取 revision 不相等即 409。
3. 必须满足 status=VALID 且 validatedRevision=revision；再次调用 DraftValidation.validate(packageId, editingContent, mapper) 并要求 Result.status=VALID、nativeCandidate 非空及 Native Schema 校验通过。
4. 从规范化 Candidate.objectTypes 投影只读 Descriptor，按 stable id 排序。不能直接将 editor JSON 视为规范化 Native 类型。响应明确标注 VALIDATED_DRAFT_ONLY。

**并发语义**：在数据库 SELECT 读取点一致的 revision r 可以被返回；若另一保存发生于该读取点之后，响应仍表示“对 r 的读取”，**不承诺直到 HTTP 响应发出时 r 依然最新**。后续对 r 的请求在新版本已提交后返回 409。这避免无法兑现的“网络响应时绝对最新”保证。

Snapshot 读取步骤：requireSnapshot(READ_SNAPSHOT) → NativeSnapshotService.get(snapshotId) 核验 JCS/SHA、JSONB 镜像、Schema 和包身份 → 投影同一 Type Descriptor；返回 LOCAL_SNAPSHOT_ONLY 而非 RELEASED。

### 3.2 不新建物理 Registry

M4 的 Registry 是按需解析服务和只读 API，不引入 Flyway 表、事件队列、后台同步或模块脚手架。实现时复用现有 Native 服务和 Controller 约束，只有当 M5/M7 实际需要独立模块时才评估模块拆分。

### 3.3 UI 方案

现有模型包详情提供独立的**“查看运行时类型”**只读入口（而非第二套对象编辑页面）。左侧列出当前来源的类型，右侧显示主键、Property 合同、sourceRef 和类型生命周期；顶部按**当前 VALID 草稿 / 本地不可变快照**切换来源。INVALID、NOT_RUN、revision 过期、无权限、空集合、网络错误按各自语义呈现。切换前遵守原有 unsaved edit navigation guard。

[低保真草案](../prototypes/m4-runtime-type-catalog-lowfi.html) 仅为浏览器内存演示，不读取 API，不构成实现证据；高保真仍须独立签收。

### 3.4 实施切片（OFIP Accepted 后才进行）

一个纵向 PR：真实 Java TypeResolver + RuntimeTypeDescriptor + 4 个只读 API + React 入口及只读界面 + PostgreSQL 17 与 Chromium 正反例 + 功能完成说明；不拆成只有空接口、没有用户效果的多个 PR。

## 4. Compatibility, Deprecation, and Migration Plan

- 现有 Editor v0.1、Native V0.2、V2/V3 历史 Flyway、不变快照、M2/M3 质量查询 API 保持不变。
- M4 不增加数据库表或修改既有 Flyway；没有生产 SchemaRelease/Activation，更不改造当前 JWT/OIDC 到 HttpSession。
- 当前 Package Candidate 的 version=0.1.0 是模型声明值；不得用于覆盖用户草稿 revision 或不可变快照身份。
- 若未来 M10 引入正式 SchemaRelease，需要显式新增来源类型及迁移/兼容决议，不能将 LOCAL_SNAPSHOT 隐式当作 PUBLISHED。
- M5 Binding 默认引用 Snapshot TypeRef，保存 Binding 时仍须验证绑定到该版本的 schema；模型后续修改不会重定向已有 Binding。

## 5. Test Plan（**计划，非已执行测试**）

| 测试 | 正常路径 | 负例或变更 |
|---|---|---|
| Native 权威性 | Supplier / PurchaseOrder VALID 后生成 Candidate 再取 Descriptor | 编辑器非 ENUM 空数组、空 label 经规范化；非法 schema 拒绝 |
| 版本 | 相同 snapshotId 多次查询相同结果 | 保存后请求旧 draft revision 返回 409；历史快照不变 |
| 字段 | 六种 Property 类型及可选字段如实返回 | 非法 PK、未知类型、重复类型 ID，按现有 Validate 阻断 |
| API | 列表稳定按 id 排序，单包 50 种类型可读取 | 不接受 cursor/latest/任意 raw SQL |
| 安全 | JWT 已授包能读；mvp-local 隔离测试库能读 | JWT 缺身份 401、无包授权 403；非本机 profile 启动不放行 |
| 可靠性 | 真 PG17 / Boot API / Chromium：建模→校验→运行时目录→详情 | PG 不可用 503、快照镜像/摘要不一致 500、保存并发 |
| 回归 | M1 草稿和本地快照、M2/M3 质量故事不回退 | 保留既有 API、Flyway 与 UI 编辑态 |

验收必须区分 API 合同测试、真实 PG17、浏览器 E2E、Windows 11 用户安装实测；未运行必须记录 NOT RUN。提案文档无需伪称完成这些测试。

## 6. Rejected Alternatives

1. **直接从 editingContent 序列化 TypeDescriptor**：跳过 Native Candidate 规范化与完整校验，拒绝。
2. **直接使用包的 0.1.0 声明版本或者 latest**：不能证明草稿修订身份，拒绝。
3. **新建独立持久 Type Registry 表 + Worker**：当前仅需最多 50 类型/包的只读目录，风险与迁移成本不成比例，延后。
4. **独立 /api/runtime/** URL**：两套 SecurityConfig 都会 denyAll；为 M4 仅新增 4 个只读 API 时复用现有 /api/model/** 更稳妥。
5. **单包目录引入 HMAC 游标/跨包搜索**：已有限 50 类型上限，额外一致性与权限协议无必要，拒绝。
6. **复制一套 ObjectType 编辑器**：增加用户心智负担且破坏原导航/未保存保护，拒绝。
7. **M4 顺便做 M5/M7/企业身份/Agent**：会降低单 PR 验收可见性、扩大核心合同风险，拒绝。
