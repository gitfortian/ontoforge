## Motivation

用户查到“受影响设备 17 台”时，需要知道使用哪份模型和 Binding、读了哪些表列、17 是完整请求还是已知子集，以及源变化后能否继续翻页。
源列改类型、关系断链或查询超时时，用户应能看到可解释的失败与修复路径，不能把“没有结果”误认为“没有影响”。

评审证据基线为 main `6968ea0804f57b2b82f237e37f812bcadb32f343`：

- `QualityMvpController.traceSet/objectSet()` 已返回 boundRevision、Mapping SHA-256、来源表列、断链计数，并在单请求只读 `REPEATABLE_READ` 下计数/分页。
- `verifiedMapping()` 重新验证允许表列是否仍存在，失配返回 `BINDING_SCHEMA_DRIFT`；`mappingFingerprint()` 摘要来自映射 JSON，并非源数据内容或数据库历史水位。
- 当前游标绑定查询、模型修订与映射指纹，不固定跨 HTTP 的来源数据；[M2](../implementation/M2-ObjectSet-制造质量影响集合实现与验收-20261017.md)、[M3](../implementation/M3-Native-ObjectSet-对象浏览实现与验收-20261017.md) 已明确此限制。
- 现有 `QualityImpactObjectSetTest` 验证固定事实、冲突、断链、去重和游标错用；未证明并发写入下跨页历史一致性，也不是完整漂移检测测试。
- [Native Result Schema](../design/schema/objectset-result-v0.2.schema.json) 已设计质量四维，但要求 schemaReleaseDigest、indexSnapshotRef、authorizationScopeRef，不能直接装载 M10 前本机虚拟读取结果。

Issue 的“来源、时效、范围、漂移、未知”方向必要，缺口在于每个词的判定依据、检查时点、恢复动作和证据保留边界尚未明确。
成功黄金故事：用户运行一次自定义 ObjectSet 查询，在结果证据中定位模型、绑定与源表列；测试源删改列后再次查询被阻断，用户比较差异、修复映射并生成新 Binding 修订，新执行恢复且旧结果不会冒充最新。

非目标：生产连接器、跨系统强一致、CDC/增量同步、可重放的源历史仓库、企业事实全量认证、数字签名/审计合规认证、长期查询档案、Action 回执/业务结果核验。
现有 JWT 和本机隔离模式必须按真实代码分别描述；未来 yak-ops HttpSession 未实施，也不作为此次本机核心功能的前置。

## Public Interfaces

继承 M7 的 `local-query-v1` 执行信封及版本化 DTO；不修改现有 Native V0.2 Schema，也不以无真实意义的占位值绕过必填字段。

| 证据合同 | 候选内容 |
| --- | --- |
| 执行身份 | 服务端生成 `executionId/executedAt/queryDigest`；过滤值按最少必要记录，不能把原始敏感查询写进日志 |
| 版本锁 | `versionLock={typeSourceRef,payloadSha256,bindingVersions,sourceSchemaFingerprints}`；M8 加入 LinkBinding 及双端 Binding 版本 |
| 读取关联 | `sourceReadRef` 指向本 execution 的服务端 SourceReadEvidence，客户端不能提交证据冒充成功 |
| 来源读取证据 | sourceId、受控 relations 与实际使用列/连接映射、sourceSchemaFingerprint、readStartedAt/readCompletedAt、consistency、checkpoint 状态、请求范围及读取覆盖 |
| 结果冻结 | `resultSnapshotRef`、createdAt、expiresAt；仅代表有界结果内容被冻结，不叫 indexSnapshotRef、模型 Snapshot 或 PG 源快照 |
| 访问形态 | `accessMode=LOCAL_ISOLATED` 或既有受验证 JWT 模式；服务端解析的当前主体/权限，禁止客户端自填 AuthorizationContext |
| 结果质量 | `status=SUCCESS/PARTIAL/FAILED`，`accuracy=EXACT/APPROXIMATE/UNKNOWN`，`completeness=COMPLETE/PARTIAL/UNKNOWN`，`freshness=FRESH/STALE/UNKNOWN`，`answerScope=REQUESTED_SCOPE/KNOWN_SUBSET` |

`bindingVersions` 项统一为 `{kind,bindingId,revision,digest,sourceId}`，kind 区分 OBJECT/LINK；revision 沿用本机不可变修订，不冒充 Native SemVer。

其中 SourceReadEvidence 是 local profile 中可复核的读取说明，不是新的源事实权威或第三方可信证明；其名字不改变现有 Native 合同。
读取开始/结束时间是平台观察时间，不能替代源事实业务生效时间、Source Watermark 或已消费的 Checkpoint。
当前虚拟读取没有可验证的源水位时，`checkpoint={status:UNKNOWN}`，freshness=UNKNOWN；禁止生成“当前时间水位”或假 offset。
`consistency=PG_REPEATABLE_READ` 只说明一次执行的读取隔离级别；不能由该字段推出源同步已完整、历史可重放或跨系统强一致。

拟新增的公开交互为结果的“来源与范围”详情、Binding 的“比较来源结构/重新校验”，以及包范围下按 executionId 读取证据的接口；准确 API URL 随实施 PR 固化并测试。
结果详情只能查看同一可访问 execution 的证据，不能用任意 sourceReadRef 枚举其他包的数据；结果失效后仅返回安全失效原因。
证据正文和查询结果共同遵守 TTL/撤权/保留规则，不能让失效结果从独立 evidence API 再次泄露。

| 状态/错误 | 服务端与 UI 行为 |
| --- | --- |
| `BINDING_SCHEMA_DRIFT` | 阻断新读取并使相关旧结果失效；返回有资格查看的结构差异与重新校验入口 |
| 409 `BINDING_REVISION_CONFLICT` | 拒绝混合旧新 Binding；提示重开配置并执行新查询 |
| `RESULT_EXPIRED` | 410；TTL 到期/重启后无成员可翻页，明确重新查询，不静默转到新 execution |
| `SOURCE_UNAVAILABLE` / `SOURCE_TIMEOUT` | 503；FAILED，不返回旧缓存或伪造空集合；恢复后可显式重试 |
| `QUERY_ACCESS_REVOKED` | 安全拒绝并撤销相应游标/证据句柄，受限来源和对象存在性不外泄 |
| 非空孤儿引用 | M8 已核实范围内 PARTIAL/KNOWN_SUBSET，说明已知断链；不算作不存在影响 |
| 对象/属性冲突、超预算 | FAILED；无对象集合/aggregate，不用 0 代替未知，保留安全失败代码 |

预算使用 429 `QUERY_BUDGET_EXCEEDED`，来源断线/超时分别为 503 `SOURCE_UNAVAILABLE` / `SOURCE_TIMEOUT`；不沿用制造专用旧接口的 409 预算码替代新合同。

错误名称与 M5–M8 统一目录收敛；HTTP 失败在传输层使用安全错误体，不能强行包装成包含伪版本/伪 sourceReadRef 的“合法结果”。

## Proposed Changes

### 1. 查询前、执行内、翻页时的三次边界

查询前解析固定 TypeRef、验证 M5/M8 不可变 Binding 版本与来源允许状态；sourceRef 指模型来源和 sourceId 指数据来源，不能互换。
持久 Binding 仅锁 Local Snapshot，不因当前草稿编辑自动失效或升级；用户主动改绑生成新修订，历史模型身份仍可解释。
结构校验读取表/列、SQL 类型与修饰、NULL/主键要求、连接键类型等影响映射的元数据，形成规范化结构指纹。
只比较 Binding 实际依赖的结构及完整性约束；新增未使用普通列可提示，不无条件使所有 Binding 失效。

一次执行在同一来源只读连接的 `REPEATABLE_READ` 下完成源验证、所有相关事实/冲突/预算检查、去重、计数和结果物化。
DDL 竞态导致计划或读取失败时，不返回部分旧结果；结束前完成版本与权限复核，成功才发布带 sourceReadRef 的完整有界结果快照。
来源只读连接与可写控制面连接分开；权限/版本通过控制面的当前读取在执行前后及每页复核，不宣称两个连接具有原子快照。检测变化即拒绝发布结果，复核时点写入证据。
禁止以“预览 3 行正确”替代请求范围内的数据校验；源列存在不证明列的业务含义未变，语义变化仍由来源责任人复核。

后续每页按服务端句柄读取冻结成员，同时复查当前包/来源读取资格、绑定状态及依赖结构；不重新读取/拼接源成员。
来源结构复查超时或数据库断开，本期统一 fail-closed，不提供离线历史查看；返回 SOURCE_UNAVAILABLE，恢复也不能延长原 TTL。
控制面明确撤权或结构漂移后，相关游标、证据和结果句柄最迟在下一次服务端访问时失效；服务端重启清空临时结果。
权限复查和响应间仍存在并发窗口；本期不宣称已实现企业级零延迟撤权或已发浏览器内容可被收回。

### 2. 三种“快照”与两种完整性

Local Snapshot 冻结模型定义；versionLock 锁定解释规则和映射；resultSnapshotRef 冻结本次有界执行得到的结果。
这三者都不等于长期保存源数据库 MVCC 历史；源事实后续改变，新 execution 可以返回不同对象和值。
使用固定结果分页可避免同 execution 翻页漏重，但不能证明新查询仍会读到同一业务事实，或旧结果足够新鲜。

| 情况 | 质量语义 |
| --- | --- |
| 全部声明的受控 PG 请求范围读取完成，无身份/关系缺口 | completeness=COMPLETE，answerScope=REQUESTED_SCOPE；仅指该范围，不能扩成整个企业 |
| 已知非空孤儿或明确缺失的请求来源部分，允许返回有效子集 | status=PARTIAL、completeness=PARTIAL、answerScope=KNOWN_SUBSET；可为已知子集的 EXACT 数量 |
| 无法确定覆盖范围 | completeness=UNKNOWN、answerScope=KNOWN_SUBSET，不称完整；本期不能安全返回子集时直接 FAILED |
| 仅缺源业务时间/水位证明，PG 请求范围已完整读到 | 可以保证请求范围的计数精度；freshness=UNKNOWN、checkpoint UNKNOWN，不把 observedAt 当实时证明 |
| 超时、权限无法核验、身份/属性冲突、预算超出 | FAILED；accuracy/completeness/freshness=UNKNOWN，无对象/聚合值 |

“请求范围完整”与“上游业务事实已全部入库”分别解释：来源本身不完整时只能表述此 PG 范围，不得扩展成业务全集。
首期不支持近似聚合；保留 UNKNOWN/STALE 的语义，不提供没有证据的“实时”“100% 可信”标识。
后续如声明 FRESH，必须新增来源可核验的时间/水位能力、明确 freshness 规则版本及阈值、验证时钟偏差/迟到数据，经过独立评审；本期默认 UNKNOWN。
Native V0.2 的 `sourceCheckpoints` 强制非空字符串 checkpoint，且 COMPLETE 要求各 checkpoint 完整；local DTO 必须显式保留未知，不能强转成该候选格式。
未来 Native 适配要提供真实 SchemaRelease、IndexGeneration/可用替代 profile、授权范围与来源 Checkpoint，并通过新版本合同评审；不能写一个字段映射器冒称兼容。

### 3. 漂移复核与恢复闭环

1. 结果或 Binding 页面出现漂移状态；阻断继续查询和失效结果翻页，保留可查看的配置修订历史。
2. 用户主动点击“比较来源结构”，看到旧/新依赖字段、类型、键约束的差异，以及无法自动检测业务含义变化的边界。
3. 用户修正来源或编辑映射；系统做类型/身份/关系校验，给出预算内预览和校验范围。
4. 用户明确确认保存新 Binding 修订，CAS 防止覆盖另一位使用者的修改；旧 revision/digest 不改写。
5. 新查询创建新 execution/sourceReadRef/resultSnapshotRef；页面清楚区分旧结果已失效与新结果已完成。

不提供“忽略漂移继续读”“按同名列自动重绑”或未经复核恢复按钮；新增未使用列的提示可以继续，实际依赖变化必须复核。
源表被删除重建即便列名相同也需检查可辨识的关系身份与依赖结构；元数据仍相同的业务语义替换不在自动检测保证范围内。
来源恢复连接后不自动把已漂移/撤权版本恢复为有效；临时断线可在原 TTL 内显式重试，结构或权限变更需相应复核。

### 4. 最小证据保留与责任

默认结果与可访问详细证据共同存放于 M7 的有界临时存储，TTL 5 分钟、重启失效，不持久归档原始源行或完整业务载荷。
源记录没有稳定定位键时，证据定位到表列、映射、版本与读取执行，明确“行级定位不可用”；不可把 PG ctid/当前时间伪装为稳定证据。
日志仅保留最少 executionId、耗时、状态、安全错误代码，排除密码/连接 Token/原始业务值/完整 SQL 参数；保留时长和日志清理由实现运行手册明确。
证据是服务端读取事实的说明，当前不含签名、防篡改存储或长期审计，不能作为生产合规承诺。
模型服务拥有模型版本，Binding 服务拥有修订与漂移复核，来源适配器提供可验证读取信息，查询服务组合信封和失效；UI 只展示，不自行推断完整/新鲜/授权。

### 5. 一个可验收切片与后续边界

首个 M9 实现 PR 交付“查询证据面板→修改隔离来源列→阻断→差异复核→保存新 Binding→重新查询”的完整闭环。
复用 M5–M8 已有信封和最低漂移/权限门禁，不重新实现全部 Query Planner、对象读取或关系运行时。
新增同一执行的源读说明、依赖结构差异、明确 TTL 与失效恢复，覆盖 M7 对象查询和已交付的 M8 一跳；未完成的 M8 桥表/二跳测试按切片列 NOT SELECTED。
源水位适配、缓存离线读取、持久结果档案、跨来源同步和生产撤权 SLA 各自需要后续用户故事和合同签收，不纳入首个 PR。

## Compatibility, Deprecation, and Migration Plan

- 保留现有 M2/M3 DTO 与 `boundRevision/sourceFingerprint` 含义，不能把历史 Mapping 指纹重命名为源事实版本；UI 如迁移须明确入口/行为和旧调用方兼容。
- local-query-v1 若仍未实现，随其 Accepted 合同一起实施；若已存在消费者，新增必填证据/错误语义须版本化及兼容测试，不静默改变解释。
- 历史 Binding 修订与 Local Snapshot 不重写；漂移状态是当前可执行性观察，不能改变历史配置摘要。已失效结果不得导回为当前查询结果。
- 本期临时结果与证据不需要永久源事实表；需要记录结构基线或修订时，使用实施时下一个未占用的前向 Flyway，绝不修改 V1–V6 或清库修复。
- 清除临时结果不会回滚源事实；修复来源和回退 Mapping 都需重新验证，旧版本不自动获得新授权。
- 正式发行、跨源身份、Action/Outcome 及 Semantic Execution Record 的迁移：None，本提案不引入这些运行时。

## Rejected Alternatives

1. **直到 M9 才加最低证据与授权**：M5–M8 已读取来源，缺少最低门禁会先产生错误产品语义；前置最小合同，M9 收口可复核性与恢复流程。
2. **将 Mapping hash、模型 Snapshot 或 executedAt 当来源水位**：这些只标识解释规则或平台时钟，没有源进度证明；明确 UNKNOWN 并说明作用域。
3. **每页重新查询后声称稳定分页，或跨页长持 RR 事务**：前者会漏重/计数漂移，后者占连接且难以撤权；采用预算内一次物化的临时结果与每页重新授权。
4. **源不可用时静默用旧缓存，或错误返回空数组/0**：用户无法区分旧事实、未知与无影响；本期 fail-closed，若未来离线历史模式另订合同。
5. **记录全部源行与凭证以便“完整审计”**：扩大敏感数据面且缺长期保留/授权治理；只保留有界最少读取说明，持久审计另案设计。
