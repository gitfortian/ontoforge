# Yak Ops 模块结构与依赖核验

> 研究日期：2026-10-17（Asia/Shanghai）。用途：为 OntoForge 的完整工程模块规划提供外部源码证据；本文件不构成 OntoForge 的第二套架构权威。
>
> 核验仓库：[weifuwan/yak-ops](https://github.com/weifuwan/yak-ops)，分支 `main`，固定提交 [`85338827bdbb745eaa6a017031640674a298a4f9`](https://github.com/weifuwan/yak-ops/commit/85338827bdbb745eaa6a017031640674a298a4f9)，提交时间 **2026-10-15 13:04:09 +08:00**。下文所有 Yak Ops 证据链接均固定在该提交，避免把未来主分支变化混入本次规划。
>
> 方法：浅克隆并逐个解析全部 `pom.xml`，核对源码、npm 配置、架构测试和工作流；未执行外部项目代码，未安装依赖，未运行其构建或测试。因此下文“存在测试”仅指源码事实，不代表本次测试通过。

## 1. 可直接用于规划的结论

1. **源码事实**：根 `yak-ops` 是 Maven Parent/Reactor，`io.yak.ops:yak-ops:1.2.0`，Java 21，Spring Boot Parent 3.3.13；直接注册 **21 个模块路径**。递归展开 business 与三组 plugin 聚合后，是 **32 个子项目 + 根项目，共 33 个 POM**。根注册顺序不是模块调用层级。[根 POM][root-pom]、[Business POM][business-pom]、[Datasource 聚合][datasource-pom]、[Task 聚合][task-pom]、[Scheduler 聚合][scheduler-pom]
2. **源码事实**：`yak-flow/`、`yak-ops-plugins/` 只是目录，不存在各自的 `pom.xml`；根 Reactor 直接列出它们下面的实际 Maven 项目。不能把这两个目录画成已有 Maven 聚合模块。[根 POM][root-pom]、[YakFlow 目录][flow-tree]、[Plugins 目录][plugins-tree]
3. **源码事实**：`platform → dao → common`；`core → configuration`；`spi` 没有内部模块依赖。不能因为目录并列就推导 `core → platform`、`dao → core` 或 `platform → business`。[Platform POM][platform-pom]、[DAO POM][dao-pom]、[Core POM][core-pom]、[SPI POM][spi-pom]
4. **源码事实**：`spi` 只拥有通用 `SpiRegistry`；Datasource、Task、Scheduler 的产品扩展合同分别在各自 `plugin-*-api`。所有扩展接口不集中在 `spi`。[SPI 源码][spi-java]、[Datasource API][datasource-api-pom]、[Task API][task-api-pom]、[Scheduler API][scheduler-api-pom]
5. **源码事实**：`yak-ops-ui` 是 **一个产品 Web 应用 + 一个共享 UI 包**的 npm workspace，并非已存在多个 Web 应用；同时它有一个注册到 Reactor 的轻量 Maven POM。该 POM 没有执行 npm 的插件，正式前端构建由 CI 单独执行。[UI 根 package][ui-package]、[Web package][web-package]、[Yak UI package][yakui-package]、[UI POM][ui-pom]、[质量 CI][quality-ci]
6. **适配建议**：借鉴 Parent/BOM、职责分组、插件 API/实现分离、Boot 组装、独立执行协调、测试与分发分离；OntoForge 的领域模块与子模块应由自身完整功能合同推导，不能照搬数据同步/CDC 引擎，也不必为对齐目录立即建空模块。此项为规划判断，来源边界见 [参考项目职责与约束][agents]。

## 2. 全部真实 Maven 结构

下图 `[pom]` 表示明确声明 `packaging=pom`；`[jar]` 表示未显式设置 packaging，使用 Maven 默认 jar；`[dir]` 只是目录。根 Reactor 注册完整路径，聚合 POM 再递归注册自己的子项目。证据为 [根 POM][root-pom] 与 [Business][business-pom]、[Datasource][datasource-pom]、[Task][task-pom]、[Scheduler][scheduler-pom] 四个嵌套聚合 POM。

```text
yak-ops/                                      [pom] 根 Parent/Reactor
├─ yak-ops-bom/                                [pom] 独立版本约束
├─ yak-ops-test-utils/                         [jar]
├─ yak-ops-common/                             [jar]
├─ yak-ops-platform/                           [jar]
├─ yak-ops-dao/                                [jar]
├─ yak-ops-spi/                                [jar]
├─ yak-ops-configuration/                      [jar]
├─ yak-ops-core/                               [jar]
├─ yak-flow/                                  [dir] 无 POM
│  ├─ yak-flow-runtime/                       [jar]
│  ├─ yak-flow-connector-base/                [jar]
│  ├─ yak-flow-connector-jdbc/                [jar]
│  └─ yak-flow-connector-cdc-mysql/           [jar]
├─ yak-ops-business/                           [pom]
│  ├─ yak-ops-business-datasource/             [jar]
│  ├─ yak-ops-business-task/                   [jar]
│  └─ yak-ops-business-schedule/               [jar]
├─ yak-ops-plugins/                            [dir] 无 POM
│  ├─ yak-ops-plugin-datasource/               [pom]
│  │  ├─ yak-ops-plugin-datasource-api/        [jar]
│  │  ├─ yak-ops-plugin-datasource-jdbc/       [jar]
│  │  └─ yak-ops-plugin-datasource-all/        [jar] 依赖打包入口
│  ├─ yak-ops-plugin-task/                     [pom]
│  │  ├─ yak-ops-plugin-task-api/              [jar]
│  │  ├─ yak-ops-plugin-task-data-sync/        [jar]
│  │  └─ yak-ops-plugin-task-all/              [jar] 依赖打包入口
│  └─ yak-ops-plugin-scheduler/                [pom]
│     ├─ yak-ops-plugin-scheduler-api/         [jar]
│     └─ yak-ops-plugin-scheduler-quartz/      [jar]
├─ yak-ops-task-execution/                     [jar]
├─ yak-ops-boot/                               [jar] Spring Boot 入口与组装
├─ yak-ops-e2e/                                [jar] 测试代码为主
├─ yak-ops-ui/                                 [jar] 轻量 Maven 注册 + 独立 npm workspace
└─ yak-ops-dist/                               [pom] assembly 发行包
```

`*-all` 是**普通 jar 项目的依赖汇集入口**，不是 `packaging=pom` 的 Reactor 聚合器；应与其上级插件聚合 POM 区分。[Datasource All POM][datasource-all-pom]、[Task All POM][task-all-pom]

根 Parent 导入 `yak-ops-bom`；BOM 本身直接继承 Spring Boot Parent，而不是反向继承导入它的根 Parent。BOM 对齐内部模块及 MyBatis、Springdoc、Quartz 等依赖版本；dependencyManagement 的条目不等于模块已经声明运行时依赖。[根 POM][root-pom]、[BOM POM][bom-pom]

## 3. 职责与源码归属

| 单元 | 已核实职责与重要边界 | 固定源码证据 |
| --- | --- | --- |
| `common` | 跨模块 DTO/VO、业务枚举、Result/ErrorCode、分页、WorkspaceContext 和工具；实际范围比“纯领域最小公共值对象”宽 | [common Java 目录][common-tree] |
| `platform` | 认证、用户、Workspace、偏好；源码包为 `io.yak.ops.security` / `workspace` / `preference`，并非统一包在 `io.yak.ops.platform` 下 | [平台源码目录][platform-tree] |
| `dao` | Entity、Mapper、Repository、Flyway；包含 security/workspace/datasource/task/schedule 等持久化归属；元数据存储采用 MySQL 依赖 | [DAO POM][dao-pom]、[DAO 源码与迁移][dao-tree] |
| `configuration` | 独立的 Typed Option、Configuration、ReadonlyConfig、参数规则及校验合同；不是应用部署配置目录，也不是本体 DSL/AST | [Configuration Java][configuration-java]、[配置源码目录][configuration-tree] |
| `core` | Source/Sink、公有 Pipeline/Transformation、RowData、LogicalType、SchemaChangeEvent、JobClient 等数据库中立的数据流合同；不是 Yak Ops 用户管理/任务业务的统一领域层 | [Core 源码目录][core-tree] |
| `spi` | Java ServiceLoader 发现、按标识注册和冲突校验的通用注册器 | [SpiRegistry.java][spi-java] |
| `flow-runtime` | 物理图、执行图、Task、Mailbox、Checkpoint、网络/输入输出运行时 | [Runtime 源码目录][runtime-tree] |
| `flow-connector-*` | 可复用 Source/Sink 适配、JDBC 读写与 MySQL CDC；不是产品平台 DAO，也不应依赖产品 Controller | [Connector Base][connector-base-tree]、[JDBC][connector-jdbc-tree]、[CDC][connector-cdc-tree]、[架构测试][architecture-test] |
| `business-datasource` | 数据源业务、凭据处理、元数据查询、连接准备；当前确实直接依赖 datasource-jdbc 和 flow-jdbc 具体实现 | [Datasource Business POM][business-datasource-pom]、[源码][business-datasource-tree] |
| `business-task` | Definition、不可变发布版本、Submission/Admission、Instance/Lifecycle、游标与指标等持久业务状态 | [Task Business 源码][business-task-tree] |
| `business-schedule` | 任务日程与注册业务；依赖 Task 业务，方向不可倒置 | [Schedule Business POM][business-schedule-pom]、[源码][business-schedule-tree] |
| `task-execution` | 当前进程拥有的派发、取消、观察、嵌入式执行所有权、日志与日程生命周期协调；通过 Task API 使用插件，不直接编译依赖 YakFlow Runtime | [Task Execution POM][execution-pom]、[EmbeddedTaskDispatcher][dispatcher-java]、[架构测试][architecture-test] |
| `plugins` 下各 `*-api` | 对应领域扩展合同与注册器；与通用 SPI 发现设施分工 | [Datasource API][datasource-api-pom]、[Task API][task-api-pom]、[Scheduler API][scheduler-api-pom] |
| 具体插件 | datasource-jdbc、task-data-sync、scheduler-quartz；产品任务插件将产品执行合同适配到 YakFlow，Quartz 实现留在调度插件 | [Datasource JDBC][datasource-jdbc-pom]、[Data Sync][task-datasync-pom]、[Quartz][scheduler-quartz-pom]、[架构测试][architecture-test] |
| `boot` | HTTP Controller、应用配置、异常/日志边界、跨模块集成装配；入口 `io.yak.ops.boot.YakOpsApplication` | [Boot POM][boot-pom]、[Boot 入口][boot-java] |
| `dist` | Assembly 输出 `yak-ops-{version}.tar.gz`，包含 Boot jar、web 静态目录、conf、脚本、JDBC 驱动目录与许可文件 | [Dist POM][dist-pom]、[Assembly][assembly] |

**适配判断**：OntoForge 可复用工程职责命名，但自身 `core` 必须承载 Native Ontology 合同；这与 Yak Ops 的数据流合同是对应的“核心所有权原则”，并不是相同领域模型。是否把 common 的 DTO/VO 范围收窄，是否让业务仅依赖接口，属于 OntoForge 的明确设计选择，不能写成 Yak Ops 已经如此实现。

### 4.4 可执行的架构限制

Boot 的 ArchUnit 测试明确限制：Core 不依赖 Runtime/Business/Boot；Runtime 不依赖 Business/DAO/Boot；Connector 不依赖产品 Business/DAO/Boot 或 Task/Datasource 插件包；Business 不依赖 Boot 或 task-execution；task-execution 不依赖 Boot/Runtime/Connector；data-sync 插件不依赖 Business/DAO/Boot；Datasource Business 不依赖 Task 插件；Quartz 类型只在 Quartz 插件内，Task Business 不依赖 Schedule Business。[BackendArchitectureTest.java][architecture-test]

此测试还验证预期模块包确实被导入，并用实际违规测试夹具验证规则能发现违例。它是**具体规则集合**，没有声明全仓库任意 package 间都自动无环；不能将其描述为已经存在全局 cycle 检查。[BackendArchitectureTest.java][architecture-test]

**适配建议**：OntoForge 规划中的核心合同、平台安全、持久化与业务编排应画清方向，并在出现真实多模块后添加相应架构测试；若将业务依赖具体 JDBC 实现调整为依赖 Port，应明确这是本项目的适配优化，不能称为对源项目依赖关系的逐字复制。

## 5. 前端 npm 结构与 Maven 的真实关系

```text
yak-ops-ui/
├─ pom.xml                         Maven 子项目；没有 npm 构建插件
├─ package.json                    private npm workspace / 根开发工具
├─ package-lock.json               npm 锁文件
├─ apps/web/
│  ├─ package.json                 @yak-ops/web
│  ├─ main.tsx / index.html        应用入口；无 src/ 中间层
│  ├─ app/<domain>/                页面、局部状态和交互
│  ├─ app/layout/ + app/router/    产品 Shell 与入口装配
│  ├─ service/<domain>/            API、请求响应类型、参数适配
│  ├─ service/http/                唯一 HTTP transport
│  ├─ context/ hooks/              应用状态与实际复用 Hook
│  ├─ themes/ public/ assets/      Token、主题与资源
│  └─ vite.config.ts              web root；输出 ../../dist
├─ packages/yak-ui/
│  ├─ package.json                 @yak-ops/yak-ui
│  └─ src/                        通用组件与公共导出
├─ scripts/                        架构与契约检查
├─ tests/e2e/                      Python Playwright
├─ docs/tooling.md                 开发验证入口
└─ FRONTEND_RULES.md               稳定前端约束
```

以上结构以 [UI 根目录][ui-tree]、[前端规则][frontend-rules]、[Vite 配置][vite-config] 和 [架构脚本][ui-architecture] 为证。`apps/web/src`、`apps/web/pages` 等目录被架构脚本明确禁止，不是本次检索遗漏。[架构脚本][ui-architecture]

| 事项 | 已核验事实 | 证据 |
| --- | --- | --- |
| 包管理 | npm `workspaces=["apps/*","packages/*"]`，根包仅维护开发依赖；当前只有 web 与 yak-ui 两个子 package | [根 package][ui-package]、[Web][web-package]、[Yak UI][yakui-package] |
| 工具 | Node `>=22.13`；Vite 6、React 18、TypeScript 5.9、Tailwind 4；具体解析版本由锁文件决定 | [根 package][ui-package]、[Web package][web-package]、[锁文件][ui-lock] |

## 8. 对旧 S0 工程规划的核验与修正建议

本节对照本次任务开始时的 [S0 工程模块规划与命名规范](../implementation/S0-工程模块规划与命名规范.md)；该文件在本轮可能由主任务扩写，本表保留“原先措辞/覆盖不足 → 源码核验”的研究依据，不成为另一套工程规范。

| 原先措辞或不足 | 核验结论 | 给主规划的适配建议 |
| --- | --- | --- |
| 用扁平 common/platform/dao/core/business/spi/plugins 列表代表完整 Yak 结构 | 只是顶层摘要，漏掉 configuration、task-execution、YakFlow 以及 business/plugin 子聚合；根与嵌套 Reactor 必须分开 | 补完整参考树与本项目目标树，标 Maven 聚合/普通模块/目录；禁止“顶层有名字就算完整规划” |
| 将 apps/web workspace 称为“多应用工作区” | 现状只有一个 Web 应用和一个共享 UI 包 | 改为“npm workspace”；本项目维持独立前端的原因属于明确适配 |
| spi 被对应为 Connector、ObjectSet、Action 的全部扩展 Port | 这是 OntoForge 的候选职责，不是 Yak 的 spi 源码事实；Yak 的领域 API 在 plugin-*-api | 区分通用发现机制与领域扩展合同，明确具体 API 的所有者 |
| 缺少 configuration 与 task-execution 的结构地位 | 前者是独立参数合同，后者隔离持久业务与执行所有权；二者都有真实消费者 | 根据 OntoForge 配置和 Action/Agent/Function 执行需求，明确是否映射及出现阶段 |
| core 只按“统一核心”命名就承载所有领域 | Yak core 的合同与 Runtime/产品层有可执行隔离约束 | 本项目按 Native 合同定义边界，不能让 Runtime、DAO 或平台产品实现倒灌到核心 |
| business 没有子域、插件没有 API/实现层次 | Yak 实际按 datasource/task/schedule 分业务，插件按类别和 api/impl/all 分组 | 本项目按完整功能限界上下文细化，不能简单止于一个 business jar |
| e2e 被泛写成跨页面/跨模块验收 | Yak e2e Maven 模块是打包 Boot 进程的真实 HTTP；UI Playwright 在 ui/tests/e2e | 明确后端进程 E2E 与浏览器 E2E 两种归属与 Gate |
| 只说 dist 正式交付，没有说明 frontend 与 Maven 衔接 | 源项目 UI Maven POM 不构建 npm；发行 assembly 消费预先生成的 ui/dist | 规划显式写清前端构建、Boot 打包、assembly 与部署边界 |
| “不推荐直接复制任务执行/调度等”停留在排除层面 | 不应复制源项目数据平台业务，但 OntoForge 自己的受治理执行需求仍要完整规划 | 给出对应本体产品需求、模块责任及落地门槛，而不是用参考领域差异省略本项目执行设计 |
| S0 只建已有功能模块 | 与源项目“按真实所有者/调用者建抽象”的原则一致；但“分期创建”不代替“完整规划” | 保留按验收闭环落地，同时为全部产品能力列目标模块、依赖、测试与迁移门禁 |
