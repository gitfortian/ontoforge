## 一、四轴成熟度与质量记录模板

每个产品能力完成时至少填写四个独立字段，不允许一次 PR 自动升级全部字段：

| 轴 | 允许值 | 判定证据 |
|---|---|---|
| 实现 | NOT_STARTED / PARTIAL / MERGED / VERIFIED_CODE | 源文件、合并 PR、同一代码 head；不能用规划 Issue 替代 |
| 自动验证 | NOT_RUN / FAILED / PASSED | 一致 SHA 的真实 CI URL、测试用例、PG/HTTP/Chromium 反例 |
| 用户验收 | NOT_RUN / FAILED / ACCEPTED | 明确操作步骤、操作者、设备环境、实际截图与缺陷单 |
| 发布状态 | NOT_RELEASED / PILOT / RELEASED | 发布版本、授权、部署与回滚证据，禁止从 CI 推定 |

**当前全局边界**：M0–M7 存在已合并实现，但不能统一写作用户实机验收通过；Enterprise IAM、通用 M8 LinkFact、M9 全局治理、M10 SchemaRelease/Activation、M11 连续 Studio、M12 Action、M13 Agent 均不得标记已上线。

## 二、正式功能合同（Core 优先）

合同中的 **输出** 是用户或 API 可直接核验的事实；**负例** 应以真实报错、HTTP 状态和无部分结果载荷为验收对象。M8 的合同是 **待开发验收设计**，不是当前已通过测试的项目。

### C01｜跨模块工作接续

- **能力归属**：`F01.05 / F21.02`；**使用者**：建模者。
- **前置与输入**：已有包/快照/Binding；**用户动作**：从已验证 Type 进入映射，再进入对象与集合。
- **预期输出与证据**：随入口传递 packageId/objectTypeId/snapshotId/bindingId/revision，返回来源可重开。
- **拒绝/异常/恢复场景**：旧绑定、不匹配类型、刷新、断网；不得暗中复用错误的版本。
- **验证方式/完成证据**：React 路由/API 参数与真实 DB 记录、浏览器回归。

### C02｜Native 手动建模

- **能力归属**：`F02.01–F02.06`；**使用者**：领域专家。
- **前置与输入**：新建独立包；**用户动作**：创建 Supplier ObjectType，定义 code(主键)/amount(DECIMAL)/status，设置 LinkType。
- **预期输出与证据**：显示模型未发布/未冻结、编辑保存 revision；可删除草稿结构并提示悬空 Link。
- **拒绝/异常/恢复场景**：重复 id、无主键、非法基数、UUID 下拉缺失（已发现 UI/API 差异）。
- **验证方式/完成证据**：Draft API、DraftValidation、NativeModelWorkspace 及真正浏览器交互。

### C03｜可恢复的验证与修订

- **能力归属**：`F03.01–F03.06`；**使用者**：建模者。
- **前置与输入**：同时打开两个编辑窗口；**用户动作**：保存 WIP、校验；另一个窗口保存后旧窗口执行 CAS 保存。
- **预期输出与证据**：409 无覆盖；本地编辑可恢复；VALID 绑定确切修订。
- **拒绝/异常/恢复场景**：网络未知不能显示成功、非法 JSON 不落库、旧 VALID 不沿用。
- **验证方式/完成证据**：PG 草稿记录、校验问题路径、冲突响应与状态截图。

### C04｜本地快照冻结

- **能力归属**：`F04.01–F04.05`；**使用者**：审阅者。
- **前置与输入**：最新草稿已 VALID；**用户动作**：执行冻结、重复冻结、历史对比。
- **预期输出与证据**：返回 LOCAL_SNAPSHOT、摘要、同幂等键的同一冻结结果。
- **拒绝/异常/恢复场景**：INCOMPLETE/INVALID 拒绝冻结、内容漂移拒绝信任、网络未知查回。
- **验证方式/完成证据**：JCS/SHA、PG snapshot/trigger、Snapshot API、Diff 界面。

### C05｜受控源发现与预览

- **能力归属**：`F06.01–F06.03`；**使用者**：数据工程师。
- **前置与输入**：测试 DB/独立只读账号/许可表；**用户动作**：选 schema/table/column、预览样本和指纹。
- **预期输出与证据**：只读返回有限来源表列/映射前样本，不暴露任意 SQL 入口。
- **拒绝/异常/恢复场景**：无 SELECT/USAGE、对象被删除、非法 schema、跨库与生产凭证均拒绝。
- **验证方式/完成证据**：PG 实测授权、SQL 只读测试、DataBinding 工作台。

### C06｜映射身份与绑定修订

- **能力归属**：`F07.01–F07.04 / F08.01–F08.04`；**使用者**：数据工程师。
- **前置与输入**：Supplier ObjectType 本地快照已锁定；**用户动作**：配置主键+属性映射、校验、保存、重开、修订。
- **预期输出与证据**：返回 Binding ID/revision/sourceFingerprint/identityDomainId，并能按当前修订读取。
- **拒绝/异常/恢复场景**：类型不匹配、重复键矛盾值、CAS 409、来源漂移和撤权。
- **验证方式/完成证据**：绑定 create/update/revisions API+只读数据库核验。

### C07｜单对象读取与值状态

- **能力归属**：`F09.01–F09.04`；**使用者**：业务用户。
- **前置与输入**：合法 Supplier Binding；**用户动作**：按存在键和不存在键读取，显式选择属性。
- **预期输出与证据**：ObjectRef 类型化主键、PRESENT/NULL/MISSING、来源证据。
- **拒绝/异常/恢复场景**：同 ObjectRef 内容冲突、无对象、字段未映射、源失效、权限撤销分别解释。
- **验证方式/完成证据**：ObjectRuntimeService + HTTP/React 真实读响应。

### C08｜Typed ObjectSet 筛选与分页

- **能力归属**：`F11.01–F11.03`；**使用者**：业务用户。
- **前置与输入**：至少两位真实测试对象及一个非命中对象；**用户动作**：配置 EQ/PREFIX/IN、排序、属性投影、分页。
- **预期输出与证据**：返回冻结本次物化结果的精确集合与不透明 cursor。
- **拒绝/异常/恢复场景**：字段非法、排序重复、cursor 篡改/过期/跨主体、空值条件误放大。
- **验证方式/完成证据**：M7 AST 服务端测试与 ObjectSetWorkspace Chromium。

### C09｜COUNT_DISTINCT/SUM 精度

- **能力归属**：`F11.04`；**使用者**：业务分析员。
- **前置与输入**：存在两条物理记录指向同一 ObjectRef 与不同数值情况；**用户动作**：分别执行 distinct 和 DECIMAL/INTEGER sum。
- **预期输出与证据**：以最终 ObjectRef 去重，总和精度不丢失，质量范围准确。
- **拒绝/异常/恢复场景**：NULL/MISSING、冲突、预算超限必须明确失败，不得返回部分准确结果或静默置零。
- **验证方式/完成证据**：PG 原始行、服务端聚合断言、UI 聚合值展示。

### C10｜结果快照和撤权边界

- **能力归属**：`F11.05–F11.06 / F19.07`；**使用者**：授权用户。
- **前置与输入**：第一查询页已返回且有下一页；**用户动作**：新增/删除来源行、撤销包权限、撤销 SELECT 后读取后续页。
- **预期输出与证据**：若纯行变化且授权仍有效，结果成员仍为当时物化集；若撤权/结构漂移则拒绝后续读取。
- **拒绝/异常/恢复场景**：游标超时/进程重启=410、签名被篡改=400、主体不符=403、预算超限=429 等按真实合同返回。
- **验证方式/完成证据**：同一 head 自动测试、冻结结果摘要、服务端错误代码和 UI 恢复证据。

### C11｜既有质量专用追溯

- **预期输出与证据**：去重对象数、路径数、断链数不互相混淆。
- **拒绝/异常/恢复场景**：批次缺失、歧义、悬空关联及过期修订。
- **验证方式/完成证据**：现有质量 MVP PG+HTTP 及浏览器回归。

### C12｜M8.1 Link 外键与一跳

- **能力归属**：`F08.05 / F09.05–F09.06 / F11.08`；**使用者**：集成/领域专家。

- **预期输出与证据**：返回真实 LinkFact/端点/版本/来源，关系与最终对象分别去重。
- **拒绝/异常/恢复场景**：孤儿、NULL/空字符串、双端基数不合法、权撤销、端点不匹配和超预算。

### C13｜M8.2–M8.3 桥表/两跳

- **能力归属**：`F08.06 / F12.06`；**使用者**：领域专家。

### C14｜来源证据与质量维度

## 五、立即发现的功能缺陷及研发进入门槛

1. **M7 未填筛选条件静默忽略（阻断正确性）**：`ObjectSetWorkspace.tsx` 的 `buildSteps` 使用 `filters.filter(... value.trim()!=='')` 过滤用户添加但值为空的条件。下一修复 PR 要在执行前要求补值或删除条件，Chromium/服务端分别覆盖 `未填值 ≠ 无条件`；不能在本纯文档 PR 直接混入实现。
2. **Native UI 与服务端 UUID 类型合同不同**：`DraftValidation` 可接受 UUID/UUID 主键，而 `NativeModelWorkspace` 下拉没有 UUID 且主键仅认 STRING/INTEGER。需要明确类型/主键选择的统一合同、历史数据兼容与表单/API 回归。不得将服务端接受能力误标为前端可操作已实现。
3. **M8 遵循标准研发工作流**：先确认 LinkFact 身份/版本/方向、FK 孤儿、基数、桥表/两跳预算与权限；按 M8.1、M8.2、M8.3 分段完成 OFIP、UX-Low、UX-High、独立 PR 测试与验收，再逐项更新 `F08/F09/F11/F12` 的实现状态。
4. **不能以固定制造 QualityMVP 代替通用架构**：专用 trace-set 与 M7 泛型 ObjectSet、M8 LinkFact 具有不同来源合同；新增每个泛型功能必须使用非预置的采购场景验证。

## 六、签收门禁

- **文档功能完整性**：V1.3 29 个二级 F 都有 L3 真实正向能力；无“将来做 X”作为功能点占位；主归属唯一。
- **功能合同质量**：Core 当前和下一阶段 M8 的正例、反例、错误恢复、授权、来源、预算与版本可独立生成测试。
- **原型纪律**：M8–M11 新交互保留标准低保真→高保真签收。文档批准不构成 OFIP 审批或代码授权。
- **状态真实性**：区分服务端代码存在、自动检查通过、用户 Windows 11 人工 UAT、商业 Release；每项必须有记录。
- **产品正式签收**：由产品负责人对功能树/合同提出最终审核意见；合并文档 PR 的 GitHub 门禁与签收是独立决定。
